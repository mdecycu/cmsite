Kue-Tsí / Roasted Seeds

“Hold on. What’s going on here?”

I couldn’t help but voice the thought out loud. For, in that moment, I seemed to have been transported back into the midst of Shōkyokusai Tenkatsu’s Magic Troupe.

I’d crossed paths with Tenkatsu’s troupe long ago, before I’d started high school. They had been on tour, and on the day they arrived in Nagasaki, my aunt Kikuko and I happened upon the opening parade.

〈瓜子〉

「等等，這到底是怎麼回事？」

我忍不住把心中的疑問脫口而出。因為就在那一瞬間，我彷彿又回到了松旭齋天勝魔術團的隊伍之中。

那還是很久以前、我尚未升上高中時的事。天勝魔術團正在巡迴演出，抵達長崎的那一天，我和姨媽菊子恰巧遇見了他們的開場遊行。

老年人和棒子

誰道人生難再少？

君看流水尚能西，

休將白髮唱黃雞！

-- 蘇軾《浣溪沙》

王洪鈞先生在二十五卷第七期《自由青年》裏寫了一篇《如何使青年接上這一棒》，政大外交系主任李其泰先生讀了這篇文章很感動，特地剪下來，寄給他的老師姚從吾先生，還附了一封推薦這篇文章的信。姚先生坐在研究室裏，笑嘻嘻地連文帶信拿給我看，向一個比他小四十三歲的學生徵求意見，我把它們匆匆看過，然後抬起頭來，望著姚先生那稀疏的白髮，很誠懇地答他道：

「王先生在文章裏說得很明白，他說『首先不必談如何使青年接上這一棒，倒要看看如何使老年們交出這一棒』。站在一個青年人的立場，我所關心的是：第一、從感覺上面說，老年人肯不肯交出這一棒？第二、從技巧上面說，老年人會不會交出這一棒？第三、從棒本身來說，老年人交出來的是一支什麼棒？我擔心的是，老年人不但不肯把棒交出來，反倒可能在青年人頭上打一棒！」

姚先生聽了我的話不禁大笑，我也感到很好笑，但在我們兩個人的笑臉背後，我似乎看到果戈里（Nikolai Vasilyevich Gogol）的句子，我感到我們兩個人的笑都該是「含著淚水的」！

「如何使青年接上這一棒」？這是一個古老的問題。《莊子》天道篇的後面，記載那個斲輪老手對桓公說的幾句話，實在很有餘味：

「斲輪徐，則甘而不固；疾，則苦而不入。不徐不疾，得之於手而應於心，口不能言，有數存焉於其間，臣不能以喻臣之子，臣之子亦不能受之於臣，是以行年七十而老斲忻輪……」

這真是老年人的悲哀！但又何嘗不是青年人的悲哀？老年人那方面感到對青年人「不能以喻」，在另一方面，青年人又感到對老年人「不能受之」，他們眼巴巴地望著老年人「行年七十」，但卻仍舊孤單地走著那沒有止境的老路，他們有熱血，他們不能不悲哀！

現年八十六歲的美國詩人羅伯特·佛洛斯特（Robert Frost）在他《生命前進著》（Life Goes On）裏寫道：

"Just a little while back, at my farm near Ripton, Vermont, I planted a few more trees. You wonder why? Well, I'm like the Chinese of ninety who did the same thing. When they asked him why, he said that the world wasn't a desert when he came into it and wouldn't be when he departed. Those trees will keep on growing after I'm gone and after you're Gone. "

不久以前，在佛蒙特州，在我那靠近瑞普頓的農場上，我種了一些樹。你猜幹嘛呢？我就像那九十歲的中國老頭子，他也做過同樣的事。當別人問他幹嘛的時候，他說當他來的時候這世界並不是一片沙漠，當他走的時候他也不願意它是。這些樹在我離去和你離去了以後，還會繼續發榮滋長的。

這種留點餘蔭的人生觀，它代表一個偉大心靈的偉大心懷，在奴隸出身的喜劇家斯塔提烏斯·凱西裏烏斯（Statius Caecilius）的《青年朋友》（Synephebi）裏，我們也可以看到那栽了樹為後人享用的老農夫，他深信上帝不但願他接受祖先的遺業，並且還願他把遺業傳授給下一代。

在活著的人裏面，沒有人能比老年人更適合做承先啟後繼往開來的工作了，老年人從死人手中接下這根棒，由於他們的身世各異，所收到的棒子也各有不同：

第一種老年人拿的是一根「莫須有的棒子」，他們根本就沒接到過這根棒，也許接到過後又丟了，他們除了麻將牌的技術外，大概什麼也交不出來，他們最大的特色就是裝老糊塗（我還看不到一個真正糊塗的老年人），他們的人生觀是「但願空諸所有，慎勿實諸所無」，他們永遠不會退化，因為根本就沒有進化，他們數十年如一日，那一日就是早睡早起一日三餐，《五代史記》漢家人傳記太后李氏向周太祖嘮叨說：「老身未終殘年，屬此多難，唯以衰朽托於始終」。其實「托於始終」的不是她那視茫茫而發蒼蒼的「衰朽」，而是那四張小白臉和一百三十二張麻將軍！

在另一方面，他們是屬於長壽的一群，他們不需要旁斯．得．利昂（Ponce De Leon）追求的那種「青春泉」（Fountain of Youth），他們青年時代雖然衰老，可是老年時代竟得不死，他們的「殘年」是難終的，孔丘罵他們「老而不死」，他們表面上雖不敢反對聖人這句話，可是在心裏卻奇怪為什麼孔老二自己七十多歲還活著？他們也未嘗不想交點什麼給青年人，可是一方面他們沒有「避此人出一頭地」的胸襟，再一方面又心有餘而力不足，自己妙手空空，對人勞心怛怛又有什麼用呢？

第二種老年人中的是一根「落了伍的棒子」。一般說來。老年人可皆議的地方不是落伍，而是落了伍卻死不承認他落伍，落伍是當然的，可是死不承認就是頑固了。《左傳》裏記石碏雖然自承：「老夫耄矣！無能為也！」但是他的內心深處，恐怕還是有點酸性反應，尤其在青年時代有過驚天動地的事業的人，到了老年「一官匏繫老馮唐」，酸勁兒就更大。康有為剛出山的時候，葉德輝、王益吾們咬定他是洪水猛獸，寫了《翼教叢編》去罵他，可是二十年後，跑在時代前面的康有為被潮流卷到後面去了；我認識的一位同盟會時代的老革命黨，當年是飛揚跋扈的豪健人物，六十年下來，他竟變成一個整天吃齋念佛寫毛筆字的老人了。好像愈是在青年時代前進的人，愈是在老年到來冥頑不靈的人。 民國七年的十月裏，梁巨川以六十歲的年紀投水殉清，當時二十六歲的胡適曾寫《不老》一文評論這件事，他說少年人應該問自己道：「我們到了六七十歲時，還能保存那創造的精神，做那時代的新人物嗎？

這問題還不是根本問題。我們應該進一步，問自己道：「我們該用什麼法子才可使我們的精神到老還是進取創造的呢？我們應該怎麼預備做一個白頭的新人物呢？」

其實做白頭新人物談何容易！在近人中，被冷紅生罵做「媚世」、被章老虎罵做「媚小生」的梁啟超庶幾近之，其他的聞人實不多見。上了年紀的人未嘗不想進步，從霍桑（Nathaniel Hawthone）《海德哥醫生的試驗》（Dr. Heidegger's Experiment）裏，我們看到那三個老頭和一個老婦在喝了「返老還童水」以後所發的狂喊：

"Gives more of this wondrous water!" cried they eagerly. "We are younger－but we are still too old！Quick give us more！"(「把這一些奇怪的水再給我們一點！」他們著急地叫著，「我們年輕些了——可是我們仍舊還太老！快點——再多给我們一點！」)

可憐的是，他們的胃口已經不能使他們消化那些青春的果實了，他們只能「反芻」（ruminate）肚子裏頭那點存貨，以「老馬之智可用也」的自負，整天販賣那些發了霉的骨董，他們即使能誨人不倦，可是他們卻不想想被誨的後生早已「愛」了，他們說後生可畏，其實真正可畏的不是後生，而是老生那些疲勞轟炸式的常談！

我想起「琵琶記」蔡公筆試中的那句對話：「老兒，你如今眼昏耳聾，又走動不得。」參加接力賽跑的人都知道接一個「走動不得者」的棒子的味兒，尤其是失敗下來，他們竟還埋怨那些接棒的人，他們從來不肯自己反省，自己跑不快還要嫉妒青年人，說青年人不行，他們恰像平劇裏邊那種衰派的老旦，自己只不過是一個角色，可是卻在任何人面前倚老賣老，這不是滑稽嗎？

第三種老年人拿的是一根「不放手的棒子」。以前監察院副院長劉哲就是一個好代表，他老先生拿棒子打人，比孔夫子還積極，孔夫子只不過是「以杖叩其脛」，可是劉副座卻和鄭板橋一樣，志在「擊其腦」，現在他死了，棒子也殉葬了，真可惜了這根殺氣洋溢的棒子！　

老年人對死亡感到恐懼，他發現什麼東西都將在突然間不屬於他，他不願看到任何東西離他遠去，因此人一到了老年，就顯得貪心而小氣，他們一方面殊求無厭；一方面「印刓敝，忍不能予」， 他們充滿了舍我其誰的自信，一點沒有成功不必在我的雅量，總覺得他一遽歸道山天下就無人救了！國失干城了！青年人失導師了！學問成絕學了！圖書館沒館長了！所以他們什麼都想一把抓，什麼都想求近功，孔夫子早就看到這一點，因此他勸老年人「戒之在得」，換成白話說，就是：「你們這些憨老漢還是休息休息吧！還是鬆開手，把棒子遞給青年人吧！」

但是話雖這麼說，貪得之心即使連說大道理的聖人也在所難免，即以勸人「戒之在得」的本人而論，孔丘說他「道不行，乘桴浮於海」，可是跟他出國的，他卻限制名額只要子路，子路的身體足可以參加接力賽跑，可是孔子仍嫌他「無所取材」，「禮記」中記孔聖臨死前「負手曳杖，消搖於門」，這個「曳」字用得太好了，杖者棒也，棒者名器，不可以假人，放乎哉？不放也！棒交不下去，一個「曳」字寫盡了他那失望而未絕望的心情，當子貢跑進去的時候，孔子感歎「爾來何遲也」！這是一個七十三歲的老教育家最後的哀呼！　

我們只看到老年人在體力上需要「杖而後能行，扶而後能立」，但我們卻很難想像一根棒子的抽象意義對他們是何等重大，他們老了，需要青年人來扶，但他並不完全放心，他還是要緊抓著棒子，一來呢，棒者，男孩子之所喜，女孩子之所欲也，有棒在手，倚之以吊青年人胃口，自然不難達到「少者懷之」的境界；二來呢，有棒子可增加他的自我信任和安全感，「姚興小兒，吾當折杖以笞之！」這是何等老當益壯的口氣！三來呢，你這年輕人，苟生異心若萌歹念而不好好扶老子，老子就給你一棒子！（老實說，凡是「博我以文，約我以禮」的人，都是能夠「擊我以棒」的人，其實這還算是好的，等而下之的，有些老前輩們，為了怕青年人有朝一日搶去了他們的棒子，他們索性先給青年人一棒子，那些專門澆青年人涼水、扯青年人後腿、說青年人樣樣不行的，就屬此類。）

西遊記就是一個好例子。取經一事，明明孫行者足可勝任，可是卻一定要派唐僧那個血壓又高、頭腦又混的肉饅頭做主角，還帶了豬八戒沙和尚兩個工讒善媚的走狗青年，唐僧根本不比孫悟空高明，只是裝得老成持重些，且年資已久，是胡吉藏的老弟子，跟姚思廉是老同學，自然在菩薩面前吃得開，緊箍咒就是唐僧的抽象棒子，孫猴子雖然也有個棒子，但在滿朝精神重於物質的邏輯下，只好被唐三藏棒住。　

老年人抓住棒子不放的另一原因，是他們的長壽心理，古人「有生者不諱死」，其實「諱」字應該校改為「知」字，許多老年人整天做著「竊比我于老彭」的好夢，不慌不忙，從來不知死之將至，據說虞舜九十五歲才把帝位「禪」出來，其老不倦勤之概可想。比照虞先生的尺碼看來，人生七十歲開始也不嫌遲。很多老年人都有大遠景，長期發展的大計畫，而這些遠景和計畫卻又和他們遲緩的腳步極不相稱的，他們只知道任重和道遠，卻不曉得日暮與途窮，陸遊的詩句道盡了他們心中的竊喜，那是：　

「自揣明年猶健在，東廂更覓茜金栽。」

白首窮盡的抱負是動人的，可惜只是礙了手腳！叔本華算是這些人裏邊最成功的，他說：「他們以為我老得要死了，看吧，等他們全死了，我還活著。」在這方面他是考第一的，可是他的自私與吝嗇也是考第一的。

新陳代謝（metabolism）本是很普通的自然現象，它的結果自然產生許多「老廢物」（waste matter），像草酸鈣（calcium oxalate）等就是，這種異化作用是一切生物活動的起點，並不值得驚怪與戀棧。紀元前六世紀，大運動家密羅（Milo）年老的時候，一天看到操場上的年輕健兒大展身手，他竟忍不住望著自己鶴骨雞膚大哭，他感歎，他不服氣，他終於不自量力，狂劈橡木而死，引起西塞羅（Marcus Tullius Cicero）在「論老年」（De Senectute）裏不少的訕笑。

有些老年人硬怕青年人厭棄他們，屠格涅夫的「父與子」裏記尼可拉．彼特洛維奇（Nikolai Petrovitch）接他兒子回來時說：「現在我們必須互相接近，並且設法相互徹底地瞭解。」（第三章）但是他的哥哥卻先感慨了：「你設法不忘掉你學過的，但是——一轉眼！——他們就證明那些都是垃圾，並且告訴你，有靈性有見識的人早就不搞這些勞什子了，並且如果你不以為嫌，一個落了伍的老腐敗就是你！這又有什麼好法子？年輕人自然比我們來得聰明！」（第六章）

後來弟弟終於悟到了，他說：「這樣看來你和我都是落了伍的人了，我們的時代過去了，唉，唉，也許巴紮洛夫（Bazarov）是對的，但是我坦白告訴你，有一件事使我難受，就在這時候，我是多麼盼望我能與（兒子）阿爾卡迪（Arkady）多親近一點，可是結果呢，我丟在後邊了，他已經向前走了，我們不能互相瞭解了。」「我從前還以為我正跟著時代做每一件事，……我念書、我研究，我嘗試在每一方面都合乎時代的要求，——可是他們還說我的日子過去了，並且，哥哥，我也開始這樣想了。」「哥哥，你知道我現在想起什麼嗎？有一次我跟我們可憐的媽媽吵嘴，她好生氣，不願聽我的話，最後我向她說：『當然了，你不能瞭解我，我們是屬於不同的兩代的人！』她被我氣壞了，可是當時我卻想：『這又有什麼法子呢？它是一顆苦藥丸，可是它必須吞下去。』你看，現在輪到咱們了，咱們的後一代也可以向咱們說：『你不是我們這一代人了，吞你的藥丸去罷！』」「是的，哥哥，好象是時候了，我們該訂做一口棺材，把兩條胳膊放在胸前了。」（第十章）　

至少我個人覺得，像尼可拉．彼特洛維奇這種老年人是可以尊敬的，他雖到了老悖的年紀，雖然在「涅盤經」的八苦中只少占了六苦，可是他仍然想做一朵「老少年」（即雁來紅Amarantus tricolor），他充滿了正常的舐犢之愛，虛心的向另一代的小毛頭們來學，也許「老狗學不會新把戲」，但他絕不就此展開「倚賣術」，「北史」穆崇傳：「老身二十年侍中，與卿先君亟連職事，縱卿後進，何宜排突也？」這就是賣老！

有些急進派的年輕人實在看不慣，他們對「老羆當道臥」的局面感到難以容忍，他們未嘗不想自己去另外找棒子，可是老年人慢騰騰地「跑」在前面，既礙了路，又擋住視野，於是年輕人想到還是乾脆去搶棒子，可是，怪事就在這兒，十次有九次，他碰到的是一位飯斗米肉十斤的腹負將軍，或是一位狡猾無比的癡頑老子，除了被飽以老拳外，連接棒預備隊的資格也要丟掉了。經書上說「老者不以筋力為禮」，可是打起人來，他們就有勁了！

王陽明說：「不有老成，其何能國？」詩經裏說：「雖無老成人，尚有典型。」一些古代的「年老成德之人」的確給了我們不少的典型，在古希臘時代，僭主庇西斯屈特斯（Pisistratus）怒問智者梭倫（Solon）：「你仗著什麼，竟這樣勇敢的反抗我？」梭倫平靜地答他道：「老年。」這些老骨頭們的高風亮節真使我們傾倒！一個人到了「七十老翁何所求」的年紀，以他的身分、地位與安全性，若還「以耽沉之利，欲役老朽之筋骸」，該是一件多麼可恥、多麼懦夫、多麼不可饒恕的事！

所以，當我們想到八十一歲的柏拉圖死時還拿著筆、八十六歲的胡佛每週還工作八十四小時、九十四歲的伊梭格拉底斯（Isocrates）還絕食殉道，再回頭看看我們這種一面通宵打牌、一面「我老了，看你們的了」的傳統、一面庸德之行庸言之謹、一面舞著棒子「杖於朝」的傳統，我們能不笑洋鬼子傻瓜嗎？　

王洪鈞先生在文章裏面又說：「我無意批評年輕人。老實說，不去分析他們所處的環境、不去瞭解他們所受的教育，光是指摘他們，都是不公平的。」　

王先生站在一個中年人的立場，他當然可以原諒青年人，可是青年人若站在一個愛真理勝於愛老師的立場，他不能不對莎士比亞筆下 full of care 的老先生說幾句「不知忌諱」的話，也正如王先生所說的：「這些話，好象是牢騷，但也是不得不發的牢騷。因為問題既已存在，與其加以裱糊，不如把它戳穿。戳穿之後，我們才能瞭解到它的嚴重，才能去思索、才能去解決。」

現在一般情形，好像只有老年為青年的安排與教訓，沒有青年自己（真正的自己，不是「代表」的「模範青年」）的心聲，與王先生的文章同期，還有一篇曾約農的「為青少年陳情」，他老先生別具隻眼，覺得「推青年所希冀者，不外五端」，其中「訓育從嚴」「生活輔導」「青年立法」等，「皆出於一般青年內心之要求而未公開表示者」，至少我個人，我認為曾老先生這種「推」法未免可怕，老年人竟這樣「推」青年人，這樣為青年人「陳情」，我們真領教他們對我們瞭解的厚度了（曾老先生若肯到中學參觀參觀那種中央集權整齊劃一的平頭教育，考察考察酷似警察局的訓導處，看看那些「學生資料袋」，再向外看看太保學生的數目，大概他又會重讀他爺爺那篇「原才」了）。

我發現在曾老先生的「五端」外，還有「外一端」，正是「青年所希冀者」，那就是老年人要我們聽話，希望老年人也「垂聽」一下我們的聲音。雖然培根（Francis Bacon）早就說我們不適於判斷，可是我們畢竟是一個窩裏的人，畢竟一同參加這場接力賽，不要總是以為你們看我們都看得那麼准，你們總該想想我們在用什麼顏色的眼睛在看你們，至少你們該想一次。

梭羅（Henry David Thoreau）在他的「瓦爾登湖」（Walden）的第一篇裏，曾有過幾段激烈批評老年人的文字，它們的神韻與氣勢是會被翻譯毀壞的：　

"What old people say you cannot do you try and find that you can. Old deeds for old people, and new deeds for new. Age is no better, hardly so well, qualified for an instructor as youth, for it has not profited so much as it has lost. Practically, the old have no very important advice to give the young, their own experience has been so partial, and their lives have been such miserable failures, for private reasons, as they must believe; and it may be that they have some faith left which belies that experience, and they are only less young than they were. "

老頭子們說你不能做這個不能做那個，可是你試一下，你就會發現你能。老的一套只該適合老傢伙，新人該有新的一套。一大把年紀很難構成做青年老師的好條件，因為它得不償失、功不補患。實際一點說，老年人不會有什麼很重要的意見給青年人，他們自己的經驗是那樣支離破碎，他們的生活又那樣慘敗，他們必須知道這些都是咎由自取，也許他們還保留一些與經驗並不符合的自信心，可是他們已經不夠年輕了。

他更激烈地否定老年人：　

"I have lived some thirty years on this planet, and I have yet to hear the first syllable of valuable or even earnest advice from my seniors. They have told me nothing, and probably, cannot tell me anything, to the purpose. Here is life, an experiment to a great extent untried by me; but it does not avail me that they have tried it. If I have any experience which I think valuable, I am sure to reflect that this my Mentors said nothing about."

我在這星球上活了三十年，從我的老前輩那兒，我還沒聽到可稱得上有價值的或熱情忠告的第一個音節，他們什麼也沒有告訴我，可能也告訴不了我什麼中肯的話。這就是生命，一個大部分沒被我體會過的經驗，他們雖然體會過了，可是對我卻沒用。如果我得了什麼我覺得有價值的經驗，我一定會想：這個經驗，我的「指導人」壓根兒還沒提過呢。

這些話足可以使老一輩的罵他忘恩負義了，可是他又接著向老人家施展了棒喝：

"You may say the wisest thing you can, old man--you who have lived seventy years, not without honour of a kind,--I hear an irresistible voice which invites me away from all that. One generation abandons the enterprises of another like stranded vessels."

你可以說那些最聰明的話，老傢伙——你活了七十年了，而且活得榮華富貴，——我卻聽到一種擋不住的呐喊，要求我不聽你的話。這一代扔掉上一代的豐功偉業就好象扔掉一條擱了淺的破船。

我不太覺得我們一定要過於刻毒地批判老年人，我也不太覺得我們一定要像放棄破船一般地放棄對他們的希望，他們之中，若真有豎起脊樑特立獨行的皓首匹夫，我們還是願意做執鞭之士的。讀過「宋史」晏敦復傳的人，都會看到下面這一段：

〔和議時，秦〕檜使所親諭敦復曰：「公能曲從，兩地旦夕可至。」敦複曰：「吾終不為身計誤國家，況吾薑桂之性，到老愈辣，請勿言。」檜卒不能屈。

這是一面好鏡子，在「水深波浪闊」的時代裏，我們正需要一些有「薑桂之性」的老辣椒們來「訓育」我們、「輔導」我們，「立」身教而為我們「法」，他們要我們苦幹，至少他自己不躺在沙發上做學者；他要我們有骨氣，至少他自己不是一個「善保千金軀」的鄉願；他要我們戰鬥，至少他自己要做「老人與海」裏面的打魚人。

一些老年人教青年人讀經，他自己總該讀過「善歌者使人繼其聲，善教者使人繼其志」的話，即使他的歌聲動人壯志可嘉，他也該問問青年人的意見，瑞斯（Cale Young Rice）在「青年人向老人說的話」（The Young to the Old）裏，他告訴老年人：　

You who are old,
And have fought the fight,
And have won or lost or left the fight,
Weight us not down,
With fears of the world, as we run!

你們老了，
打過了這場仗，
贏過，輸過，又丟下了這場仗。
當我們在奔跑，
你們對世界的恐懼，
不能把我們嚇倒。

可是，問號緊跟著我們，我們忍不住要問：有幾位老年人肯聽我們的話呢？有幾位老年人能聽我們的話呢？有幾位老年人樂意談談接棒的問題呢？

從陸機的舊賦裏，我們彷佛看到一批批的英氣耿介聲蓋士林的青年人，他們一個個都從青絲老到了白髮，他們還算是高明的人，雖然顯得老憊，還能勉強維持最後一道防線，不太肯胡來，他們的「老氣」不復以達工部所謂「橫九州」的地位了，只好以望七之年，去做「橫秋」的壯舉了！老朽昏憒賣身投靠的一輩我們不必說，即以最開明一代的老先生而論，從寫「人權與約法」時代的胡適之到寫「容忍與自由」時代的胡適之；從「人權論集」時代的梁實秋到「遠東英漢字典」時代的梁實秋，我們多少可以看出他們轉變的痕跡，弗洛斯特在他那首「預防」（Precution）裏，說他年輕時不敢做一個急進派，因為怕他年老時變成一個保守派，我並非說胡適之與梁實秋已變成保守派，我是說，他們今日的「穩健」比起當年那種生龍活虎意氣縱橫的氣概，是不大相稱的！　

公自平生懷直氣，
誰能晚節負初心？

死去的哲人的詩句已經替那些好學不倦、守經不變的耄勤之士指出一條危機，我們不惋惜錢謙益、章士釗的老不自愛，我們只惋惜黃梨洲、江亢虎的晚節難全！羅馬史家李維（Livy）曾對西辟奧．阿利坎努斯（Scipio Africanus）批評道：『Ultima Primis cedebant.』（他的晚年不及他的早年。）環顧國中，有幾個可愛的老年人能擋得住這種判決呢

病情是指出來了，可是沒有藥方，答案不是沒有，而是不需要一個越俎代庖的青年人來提供，至少就我個人而言，我不覺得我有資格去做評議員。對那些老不成器老不曉事的老爺們，我不願再說什麼，對那些老著臉皮老調重彈的老奸巨猾們，我也不願再說什麼，只是對那些以老當益壯自許、以老驥伏櫪自命的老先生們，我忍不住要告訴你們說：我們不會搶你們的棒子，我們不要鳴鼓而攻我們的聖人的棒子，我們不稀罕裏面已經腐朽外面塗層新漆的棒子。我們早已伸出了雙手，透過沉悶的空氣，眼巴巴地等待你們遞給我們一根真正嶄新的棒子！　

李敖 1961年七月十五日在碧潭山樓

《莊子．天道》中的寓言「輪扁斲輪」。

斲輪徐，則甘而不固；疾，則苦而不入。不徐不疾，得之於手而應於心，口不能言，有數存焉於其間，臣不能以喻臣之子，臣之子亦不能受之於臣，是以行年七十而老斲忻輪。

做車輪的時候，如果動作太慢、下手太寬鬆，卡榫就會削得太寬、太鬆（甘），組裝起來就不牢固（不固）；

如果下手太急、削得太快，卡榫就會削得太緊、太澀（苦），車輪部件就套不進去（不入）。

最完美的狀態是做到不慢也不急，拿捏得剛剛好。這種恰到好處的分寸，是透過雙手在實作中去感受，並由內心去神領體會的（得之於手而應於心）。

這裡面有一種巧妙的訣竅（數），是用嘴巴根本說不出來的（口不能言）。

我沒有辦法用言語把這個訣竅講明白、傳授給我的兒子（臣不能以喻臣之子），我兒子也沒辦法光憑聽我說就接過這項絕活（臣之子亦不能受之於臣）。正因為這樣，我活到了七十歲，這把老骨頭了還得自己動手削車輪。

記錄先秦工藝的《周禮．考工記》，當時對車輪的尺寸、比例、以及驗收誤差，都有精準且量化的規定。輪扁所強調的「口不能言」，是因為在最後的組裝階段，木材的物理特性必須靠「隱性手感」去完成極限公差的微調。

先秦時期的「量測工具」有四大法定測量工具，統稱為「規、矩、準、繩」：

規：圓規。用來檢測車輪的外圈（牙）是否為完美的圓形。

矩：直角尺。用來測量車輪輻條與車軸之間是否達到絕對的 90 度垂直。

準：水準器（利用水面平直原理）。用來測量車箱、車軸是否平衡。

繩：墨斗與線繩。用來拉直線、確定車轅的中心軸線。

先秦如何進行「驗收與公差管理」的？

《考工記》記錄的車輪品管檢驗方法。這些方法在現代工程學來看，就是標準的「公差與品管」：

稱重對稱（質量公差）：一個車輪由左右兩組對稱的輻條組成。

《考工記》規定：「設其輻而名其上方，張其（輪）而其（質量）均。」工匠做完兩個輪子後，要把兩個輪子放到天平上稱重。兩個輪子的重量誤差必須接近於零，如果兩邊重量不均，馬車跑起來就會劇烈顛簸或偏向。

水浮法（密度與同心度公差）：把做好的整顆木質車輪丟進水裡，看它浮在水面上的深度。如果車輪在水裡沉浮的深淺完全一致，代表這個輪子的圓心位置抓得極精準，且各部位的木材密度、厚度完全對稱。

儘管有量測與品管方法，為什麼輪扁還說「得之於手而應於心」？

既然工具、尺寸、質檢標準都一應俱全，為什麼還要強調「手感」？

這牽涉到材料科學（木工）的終極限制。

木材是活的（各向異性）：金屬可以做到固定的機械公差。但木材有年輪、有干濕度、有紋理、有軟硬不均的問題。

即使你用尺量出兩個一模一樣的卡榫尺寸，一塊稍微潮濕的木頭，跟一塊完全乾燥的木頭，其組裝時的膨脹與阻力完全不同。

極限公差無法形諸文字：在組裝的最後一刻，工匠面對的是「這塊木頭今天比較乾，刀要下得再淺半毫米」或者「這個榫眼剛好卡到樹瘤，必須多用兩分力砸下去」。

Python

為了讓熟悉 C++ 或 Java 的用戶方便使用，在 Python 2.2 中，放入 @staticmethod (靜態方法) 裝飾器的用法，以便在類別 (Class) 中定義一個不需要存取類別屬性 (Class attributes) 或實例屬性 (Instance attributes) 的方法。本質上就是一個寫在類別內部的普通函式。

核心語法與特色

  1. 不綁定參數：普通方法需要 self，類別方法需要 cls，但靜態方法不需要這兩個參數。
  2. 呼叫方式：可以用 類別名稱.方法名稱() 直接呼叫，也可以透過實例呼叫 (但推薦用類別名稱)。
  3. 無法直接存取狀態：因為沒有 self 和 cls，它無法直接讀取或修改類別或實例的變數。
class Demo:
    @staticmethod
    def my_static_method(arg1, arg2):
        # 這裡只能使用傳入的參數 arg1 和 arg2
        return arg1 + arg2

範例：日期格式驗證器

假設要寫一個處理「員工（Employee）」資料的系統。需要一個功能來檢查使用者輸入的生日格式（字串）是否正確（例如必須是 YYYY-MM-DD）。這個檢查邏輯與特定的某個員工無關，只是一個純粹的工具函式，此時最適合用 @staticmethod：

from datetime import datetime

class Employee:
    def __init__(self, name, birthday_str):
        self.name = name
        
        # 在初始化時，呼叫靜態方法來驗證資料
        if Employee.validate_date(birthday_str):
            self.birthday = birthday_str
        else:
            raise ValueError("日期格式錯誤，必須是 YYYY-MM-DD")

    # 定義靜態方法
    @staticmethod
    def validate_date(date_text):
        """檢查字串是否符合 YYYY-MM-DD 格式"""
        try:
            datetime.strptime(date_text, '%Y-%m-%d')
            return True
        except ValueError:
            return False

# ===== 如何使用 =====

# 1. 無需建立實例，直接用「類別名稱」呼叫靜態方法來測試
is_valid = Employee.validate_date("2026-08-08")
print(f"格式是否正確: {is_valid}")  # 輸出: True

# 2. 正常建立實例（內部會自動呼叫該靜態方法）
emp = Employee("王小明", "1995-05-20")

# 3. 輸入錯誤格式，觸發錯誤
# emp_error = Employee("張三", "1995/05/20") # 這行會拋出 ValueError

什麼時候該用 @staticmethod？

當你發現某個方法符合以下條件時，就應該加上 @staticmethod：

  1. 邏輯相關性：這個方法的功能在邏輯上完全屬於這個類別（例如：屬於 Employee 類別的日期驗證，或是屬於 Math 類別的平方根計算）。
  2. 獨立性：方法內部完全不需要用到 self.variable 或 cls.variable。

其實 Python 語法允許將工具函式直接寫在檔案外層，那為什麼還要保留 @staticmethod 呢？主要原因有兩個：

程式碼封裝與命名空間（Namespace）：

如果這個工具函式只跟某個類別高度相關（例如前述的 validate_date 只服務於 Employee 類別），把它塞進類別內部作為 @staticmethod，可以避免污染外部的命名空間。開發者看到 Employee.validate_date() 就會立刻明白它的依賴關係。

支援繼承與多型（Polymorphism）：

寫在類別內部的靜態方法是可以被子類別繼承或覆寫（Override）的。如果是寫在檔案外層的獨立函式，就無法享受物件導向的繼承架構。

Mojo 的底層技術、演進與未來展望— 兼論其在 AI 與異質計算（Heterogeneous Computing）時代之定位

摘要 (Abstract)

隨著大型語言模型（LLM）與人工智慧（AI）的爆發性成長，傳統計算架構正面臨「研發效率」與「執行效能」的雙重瓶頸。長期以來，AI 生態系被 Python 的高層研發便利性與 C++/CUDA 的低階極致效能割裂為「雙語言架構」（Two-Language Problem）。本文旨在探討由 Modular 團隊開發之 Mojo 程式語言，如何透過融合 Python 語法與新世代 多級中間表示（MLIR） 編譯器技術，消弭上述技術斷層。本研究將詳細剖析 Mojo 的技術起源、底層記憶體所有權機制、核心突破、當前業界實際應用案例，並對比 Rust 與 C++ 等競爭語言，最後展望其演進為全域系統級語言之未來路徑。

一、 緒論與緣起 (Introduction & Origin)

1.1 歷史背景與雙語言痛點

在人工智慧、量化金融與大數據處理領域，長年存在著軟體工程的兩極妥協。Python 憑藉親切的語法與高度動態性，成為科學研究（PyTorch、NumPy）與快速原型設計的絕對霸主；然而，Python 作為高階直譯式語言（Interpreted Language），受限於全域解譯器鎖（GIL）與高昂的記憶體開銷，無法直接壓榨硬體極限。為了將模型部署於車載晶片、邊緣裝置或資料中心，企業往往需要龐大的工程團隊將 Python 代碼手動重寫（Porting）為 C++ 或 CUDA。這種「雙語言問題」大幅拉長了產品落地週期，更埋下了大量移植 Bug 與維護包袱。

1.2 創始契機

為了解決這個全球硬體與 AI 巨頭的共同痛點，由 LLVM、Clang 與 Swift 語言的開發者——克里斯·拉特納（Chris Lattner），聯合提姆·戴維斯（Tim Davis）於 2022 年創立了 Modular 公司。創始團隊的第一性原理非常明確：不應該強迫科學家去適應複雜的 C++ 或 Rust，而是應該為全球數百萬 Python 開發者賦能，打造一款擁有 Python 外殼、卻具備 C++ 效能的系統級語言。 這便是 Mojo 的誕生起源。

二、 開發過程使用的核心技術與嘗試解決的問題 (Core Technologies & Problem Solving)

Mojo 能夠打破效能障礙，並非單純在 Python 之上套用 JIT（即時編譯），而是從編譯器硬核底層進行了典範轉移。

2.1 多級中間表示 (MLIR) 技術

傳統編譯器（如 Rust 與 C++ 所依賴的 LLVM）在處理高階抽象時，會直接將代碼下放到低階的單一中間表示（LLVM IR）。這在處理通用的標量（Scalar）計算時極為優秀，但在面對 AI 特有的「張量（Tensor）計算與矩陣並行優化」時，LLVM 無法理解高階的語意。

解決方案： Mojo 直接架構在 MLIR（Multi-Level Intermediate Representation） 之上。MLIR 允許 Mojo 在編譯期間定義多個不同抽象層級的「方言（Dialects）」。這意味著 Mojo 的編譯器可以在高層級理解矩陣乘法，在中間層級自動進行並行化與硬體暫存器對齊，在底層直達硬體指令。這使得 Mojo 天生具備極強的異質計算（Heterogeneous Computing）優化能力。

2.2 漸進式強型別與靜態結構化

Python 的動態型別雖然方便，但在運行時會帶來巨大的檢查開銷（Type Overheads），且無法被靜態編譯器優化。

解決方案： Mojo 引入了 fn 與 struct 關鍵字（對標 Python 的 def 與 class）。當開發者使用 fn 定義函數並加上靜態型別標註（如 x: Int）時，Mojo 編譯器會切換至硬核編譯模式，強制在編譯期分配固定記憶體，生成無虛擬機（Zero-overhead）的原生機器碼。

2.3 融合 Rust 的記憶體所有權機制 (Ownership & Borrowing)

為了徹底擺脫垃圾回收（Garbage Collection, GC）帶來的系統停頓（Stop-the-world）延遲，Mojo 必須實現確定性的記憶體管理。

解決方案： Mojo 吸取了 Rust 的精華，在語言層級實現了借用檢查器（Borrow Checker）與所有權生命週期管理（引入 borrowed、inout、owned 等變數標註）。最創新的突破在於 「急切銷毀（Eager Destruction）」 機制：一旦一個龐大的 Tensor 或物件在程式碼中最後一次被讀取，Mojo 會在下一行程式碼執行前立即在記憶體中釋放它，而不需要等待大括號作用域（Scope）結束。這大幅提升了 GPU 等有限硬體暫存器的利用率。

2.4 完全解耦 Python 運行時與獨立二進位編譯

解決方案： 透過 mojo build 命令，編譯器能夠將所有純 Mojo 邏輯與標準庫直接編譯為單一、無任何外部依賴的獨立二進位檔（Standalone Binary）。這徹底解決了 Python 難以封裝、缺乏可攜性的歷史頑疾。

三、 相同標的之競爭語言對比 (Competitors Analysis)在現代系統程式設計與高性能計算領域，Mojo 迎面撞上了幾大實力雄厚的對手。

3.1 Mojo vs. Rust

Rust 的防線： Rust 是目前系統程式設計的黃金標準，在高性能網路伺服器、作業系統內核、資安防禦領域擁有無可動搖的地位。其生態系（如 Tokio 非同步網路框架）極為成熟。

Mojo 的挑戰與優勢： Rust 最大的弱點在於其極度艱澀的語法與緩慢的研發速度，且在 AI 運算（矩陣、晶片驅動）上缺乏底層 MLIR 級別的優化。Mojo 透過相容 Python，讓團隊可以用 1/10 的時間寫出與 Rust 旗鼓相當的效能，並能直接 import 整個 Python 生態，這對 Rust 構成了顯著的「效率維度」威脅。

3.2 Mojo vs. C++ / CUDA C++ 的防線：

傳統自動駕駛、火箭控制、3D 遊戲引擎的核心。

Mojo 的挑戰與優勢： C++ 缺乏內建的內存安全機制，安全漏洞頻傳。更重要的是，寫 CUDA 代碼需要對 GPU 硬體架構有極深的理解。Mojo 試圖成為「下一代 C++」，讓開發者用現代化、安全的語法，自動由編譯器生成超越手寫 C++/CUDA 的並行優化。

3.3 Mojo vs. Python 與 Cython

Python 的防線： 雖然 Cython 或 PyPy 能提升 Python 效能，但它們本質上無法脫離 CPython 虛擬機的束縛，也無法生成脫離 Python 的裸機（Bare-metal）二進位檔。Mojo 則是一款真正的編譯型系統語言，本質上已與 Python 分道揚鑣，只是借用了 Python 的精美外殼。

四、 已經達成的標的與目前實際應用範例 (Milestones & Application Examples)

自 2023 年橫空出世以來，Mojo 已經取得了階段性的里程碑突破。

4.1 核心成果與開源進程全面開源核心工具鏈：

母公司 Modular 已將 Mojo 的編譯器核心與標準庫以 Apache 2.0 授權協議全面開源，徹底打消了開源社群對於商業公司壟斷技術的疑慮。

極致的極速數據： 在官方公佈的曼德博集合（Mandelbrot）演算法測試中，純 Mojo 程式碼透過自動並行化與 SIMD 優化，跑出了比純 Python 快上 35,000 倍的驚人數據。

4.2 現時實際應用範例

4.2.1 邊緣運算與自動駕駛（Edge AI & Autopilot）

在自動駕駛與機器人領域，模型權重（Weights）確定後，需要將矩陣相乘代碼移植到嵌入式車載晶片上。目前已有多家前沿自動駕駛與硬體製造商，開始引入 Mojo 的編譯器將模型直接轉譯為獨立的、符合硬體指令集（如 ARM 向量指令）的二進位檔。這省去了以往將 Python PyTorch 模型手動翻譯成 C++ 的漫長陣痛期。

4.2.2 大規模大模型（LLM）推論基礎設施（MAX 平台整合）

Modular 團隊將 Mojo 語言與其旗下的 MAX（Modular Accelerated Xecution）推論引擎深度深度綁定。目前在雲端伺服器佈署開源大模型（如 Llama 3/4 等）時，使用 Mojo 撰寫的自訂注意力機制核心（Custom Attention Kernels），在非 NVIDIA 晶片（如 AMD 最新 Instinct 系列加速卡）上成功跑出了逼近甚至超越傳統 CUDA 封裝的超低延遲推論性能，這為打破晶片市場的壟斷提供了底層技術支撐。

4.2.3 高性能資料解析與預處理工具（Data Pipeline Acceleration）

在大數據與 AI 訓練前期，清洗、解析數百 GB 的純文字（JSON、CSV）是一大效能黑洞。社群與企業已開始使用 Mojo 重寫這些 I/O 與字串解析模組。得益於其沒有 GC 的快速記憶體釋放，數據管道的處理速度大幅超越了傳統的 Python/Pandas 架構，且比 C++ 專案更易於維護。

五、 未來展望與結論 (Future Outlook & Conclusion)

5.1 未來演進路徑與挑戰

Mojo 要真正建立「大一統」的王國，未來仍需跨越以下兩大挑戰：

全面補齊非 AI 領域的系統級基礎設施： 雖然 Mojo 在矩陣、記憶體和硬體加速上無懈可擊，但在傳統系統程式設計高度依賴的「非同步網路通訊（Async Net IO）」、多執行緒併發 HTTP 服務、原生圖形介面（GUI）上，其標準庫仍有很大的空白需要社群共同補齊。

Freestanding 裸機操作系統層級的解耦： 未來 Mojo 需要發展出類似 Rust #[no_std] 的極致精簡模式，才能真正攻佔微控制器底層韧體、甚至用來撰寫全新的操作系統內核。

5.2 結論 (Conclusion)

Mojo 不僅僅是一門新興的程式語言，更是 AI 與硬體異質計算時代下，編譯器技術演進的必然產物。它精準地洞察了傳統軟體工程中「效率」與「效能」不可兼得的痛點，透過 MLIR、現代所有權管理系統以及高度相容 Python 的語法設計，打破了工業界維持了數十年的雙語言包袱。儘管作為一門年輕的語言，其外圍非同步網路生態仍有待時間淬鍊，但 Mojo 「用 Python 的難度，提供超越 C++ 的效能」這項降維打擊武器，註定將在未來的 AI 基礎設施、大數據與高性能系統程式設計版圖中，強勢劃分出屬於自己的半壁江山。

將物質本質視為數學對稱性核心概念

1. 對稱性決定物質與力不變性與守恆：

諾特定理（Noether's Theorem）證明，每一個連續的數學對稱性都對應大自然的一個物理守恆定律（例如時間平移對稱對應能量守恆）。

2. 規範場論（Gauge Theory）：

基本粒子之間的相互作用力（電磁力、弱力、強力）是由「局部規範對稱性」嚴格要求的結果；換言之，力是為了維持對稱性不變而必須存在的補償場。

將物質與力的本質視為「數學對稱性」，不僅可以解釋輻射傳遞能量的現象，更提供了目前物理學中最深刻、最本質的底層機制驗證。

在現代物理（量子場論與規範場論）的框架下，輻射傳遞能量（例如電磁波、光子傳播）正是「維持數學對稱性」的必然結果。

從以下三個層次可理解此一驗證與解釋：

一、 輻射是局部規範對稱性的必然產物

在經典物理中，電荷、電場、磁場和電磁波被當作既定的自然現象。但在對稱性的視角下，順序完全反了過來：因為宇宙要滿足某種數學對稱性，所以必須存在電磁輻射。

相位對稱性（U(1) 對稱性）：量子力學中，描述電子的波函數具有一個「相位」（Phase）。如果同時改變宇宙中所有電子的相位（全局對稱性），物理定律不變。

局部化（Local Gauge）的挑戰：如果希望物理定律在「不同時間、不同地點」各自改變相位也能保持不變（局部對稱性），數學上就會出現矛盾。

輻射（光子場）的誕生：為了修正這個矛盾，數學上必須強行引入一個全新的幾何場來「抵消」因地點不同而產生的偏差。這個為了補償、維持對稱性而誕生的場，就是電磁場（規範場）。

所以當電荷運動時，電磁場產生的波動（即電磁輻射、光子）在空間中傳播並帶走能量。之所以透過輻射傳遞能量，本質上是宇宙在跨越時空維持「U(1) 數學對稱性」的動態調整過程。

二、 輻射之所以能傳遞能量是時空對稱性的推論

輻射不僅僅是波，它還攜帶著實實在在的能量與動量。此現象可以用諾特定理（Noether's Theorem）得到最完美的對稱性解釋：

從時間平移對稱性推向能量守恆：物理定律在昨天、今天、明天都一樣，此一時間上的對稱性，在數學上可直接推導出「能量守恆」。

從空間平移對稱性推向動量守恆：物理定律在世界各地、甚至在月球上都一樣，這種空間上的對稱性，可推導出「動量守恆」。

當一個激發態的原子發射出輻射（光子）時，原子系統失去了能量與動量。根據對稱性要求的守恆定律，這些能量與動量絕對不會憑空消失，它們必須被賦予給這個維持對稱性的「規範場」（光子）。當輻射傳播並被另一個物體吸收時，能量與動量再次轉移。

因此，輻射傳遞能量的物理行為，正是時空對稱性（守恆）與內部對稱性（交互作用）交織運作的具體驗證。

三、 現代前沿：這如何改變我們對「能量與物質」的看法？

在傳統觀念中，我們會覺得「物質（如電子）是實體，它發出輻射（如光子）去傳遞能量給另一個實體」。

但在數學對稱性的理論中：

物質與輻射都是「幾何對稱性的激發態」。

電子是物質場的激發，光子是規範場的激發。

能量不是一種像液體一樣流動的物質，而是群論（Group Theory）變換中的一個「守恆不變量」。

約翰·洛克 (John Locke) 的 "人類理解論"（An Essay Concerning Human Understanding, 1689年出版）是西洋哲學史上的經典巨著。這本書奠定了經驗主義（Empiricism）的基礎，主要探討人類知識的起源、性質、範圍以及限制。

洛克的核心理念可以拆解為以下四個主要面向：

一、拒絕天賦觀念 (Critique of Innate Ideas)

洛克在書中第一卷花費大量篇幅，強烈反駁笛卡兒等理性主義者所主張的「天賦觀念」(如上帝的概念、邏輯幾何公理是與生俱來的)。

  1. 白板說 (Tabula Rasa)：洛克認為人類的心靈在出生時就像一張「白紙」或「空白的黑板」，沒有任何預設的印記。
  2. 經驗的印記：大腦中所有的知識和觀念，都是在出生之後透過後天的經驗、學習和感官接觸才寫上去的。

二、觀念的起源 (The Origin of Ideas)

既然心靈是白紙，觀念從何而來？洛克認為只有兩個來源：

  1. 感官感覺 (Sensation)：我們透過眼睛、耳朵、皮膚等感官，接收外部世界的物理刺激 (如看到紅色、感覺到熱、嚐到甜味)。
  2. 心靈反省 (Reflection)：我們的大腦對內在活動的自省與覺察 (如思考、懷疑、相信、意願)。

洛克進一步將觀念分為兩類：

  1. 簡單觀念 (Simple Ideas)：被動接收、無法再分割的基礎元素 (如「黃色」、「冷」、「硬」)。
  2. 複合觀念 (Complex Ideas)：心靈主動將多個簡單觀念進行組合、比較或抽象化後產生的複雜概念 (如將「四條腿」、「毛茸茸」、「汪汪叫」組合成「狗」的概念)。

三、第一性質與第二性質 (Primary vs. Secondary Qualities)

為了全面解釋物體如何引發我們心靈中的觀念，洛克將物體的性質分為兩類：

  1. 第一性質 (主要性質)：物體本身客觀存在的物理屬性，不論有沒有人看見都不會改變。例如：形狀、體積、數量、運動或靜止。
  2. 第二性質 (次要性質)：物體本身不具備、而是透過其物理結構刺激我們的感官，在我們心靈中產生的客觀主觀感受。例如：顏色、聲音、味道、溫度 (「蘋果是紅的」其實是光線與眼睛互動後，在心中產生的第二性質)。

知識的範圍與限制 (The Limits of Knowledge)

洛克將知識定義為「心靈對我們觀念之間符合或不符合的知覺」。這意味著，我們無法直接認識客觀世界本體，只能認識由感官傳遞到大腦中的「觀念」。

  1. 實體 (Substance) 的不可知：洛克指出，我們雖然可以用「支持者」的概念來想像一定有一個物體本體支撐著這些性質，但我們永遠無法得知那個「實體」究竟是什麼 (這為後來的懷疑論埋下了伏筆)。
  2. 知識的等級：他將知識由高到低分為直覺知識 (最確定，如A=A)、論證知識 (需要推理，如數學證明) 和感性感知 (對外在世界存在的知覺，確定性最低)。
  3. 理性的界限：洛克提醒大腦的認知能力是有限的。人類不應該去追求超越經驗之外的形而上學空論 (如靈魂的物理結構)，而應該專注於對生活、科學和道德有實質幫助的實用知識。

過度反應

市場出現一個負面消息，投資人可能過度解讀，造成股價跌幅超過基本面所合理支持的程度。

因此，疫情提供了一個非常特殊的研究環境，可以觀察投資人如何在極端不確定性下做出決策。

孟子

人之患，在好為人師。

人最大的毛病，就是自以為高明，總想著去指導別人。

孟子離婁上:

Mencius said, The power of vision of Li Lou, and skill of hand of Gong Shu, without the compass and square, could not form squares and circles. The acute ear of the music-master Kuang, without the pitch-tubes, could not determine correctly the five notes. The principles of Yao and Shun, without a benevolent government, could not secure the tranquil order of the kingdom. There are now princes who have benevolent hearts and a reputation for benevolence, while yet the people do not receive any benefits from them, nor will they leave any example to future ages - all because they do not put into practice the ways of the ancient kings.

孟子說：「憑著離婁極佳的視力，以及公輸子極高的巧手，如果不用圓規和曲尺，也無法畫出標準的方圓。憑著師曠敏銳的聽力，如果不用六律，也無法校正五音。聖王堯舜治理天下的原則，如果沒有仁政，也無法安定天下。現在有些國君雖有仁愛的心腸與仁慈的名聲，卻讓老百姓無法受到實惠的恩澤，也無法成為後世的法度——這全是因為他們沒有實踐先王之道的緣故。

Hence we have the saying: "Virtue alone is not sufficient for the exercise of government; laws alone cannot carry themselves into practice." It is said in the Book of Poetry, "Without transgression, without forgetfulness, Following the ancient statutes." Never has any one fallen into error, who followed the laws of the ancient kings. When the sages had used the vigour of their eyes, they called in to their aid the compass, the square, the level, and the line, to make things square, round, level, and straight: the use of the instruments is inexhaustible. When they had used their power of hearing to the utmost, they called in the pitch-tubes to their aid to determine the five notes - the use of those tubes is inexhaustible. When they had exerted to the utmost the thoughts of their hearts, they called in to their aid a government that could not endure to witness the sufferings of men - and their benevolence overspread the kingdom.

所以我們有這樣的話：「單憑美德不足以治理政事，單靠法令無法自己實行。」《詩經》上說：「不犯過失，不忘法度，遵循著古代的常規。」遵循先王法度而犯錯的人，從來沒有過。當古代聖賢用盡了眼力，便借助圓規、方尺、水準器和墨線，來使物品達到方正、圓滑、水平與筆直，這些工具的妙用是無窮的。當他們用盡了聽力，便借助定音律管來確定五音，這些律管的妙用也是無窮的。當他們用盡了心思，便借助「不忍心看見人類受苦」的仁政，於是他們的仁慈便覆蓋了全天下。

Hence we have the saying: "To raise a thing high, we must begin from the top of a mound or a hill; to dig to a great depth, we must commence in the low ground of a stream or a marsh." Can he be pronounced wise, who, in the exercise of government, does not proceed according to the ways of the former kings? Therefore only the benevolent ought to be in high stations. When a man destitute of benevolence is in a high station, he thereby disseminates his wickedness among all below him. When the prince has no principles by which he examines his administration, and his ministers have no laws by which they keep themselves in the discharge of their duties, then in the court obedience is not paid to principle, and in the office obedience is not paid to rule. Superiors violate the laws of righteousness, and inferiors violate the penal laws. It is only by a fortunate chance that a State in such a case is preserved.

所以我們有這樣的話：「要把東西築高，必須從土堆或山丘的頂端開始；要把地挖得很深，必須從河流或澤地的低窪處開始。」在治理政事時，如果不按照前王的道路去做，能稱得上是有智慧的人嗎？因此，只有仁德的人才適合居於高位。如果一個沒有仁德的人居於高位，他就會把自己的惡行散播給底下的眾人。當君王沒有審查政務的原則，大臣也沒有自我約束、盡職守法的依據時，那麼在朝廷上就不遵循正道，在官署中也不遵守法度。上司違背了道義，下屬觸犯了刑律。處在這種情況下的國家能夠存活下來，純粹是幸運罷了。

Therefore it is said, "It is not the exterior and interior walls being incomplete, and the supply of weapons offensive and defensive not being large, which constitutes the calamity of a kingdom. It is not the cultivable area not being extended, and stores and wealth not being accumulated, which occasions the ruin of a State." When superiors do not observe the rules of propriety, and inferiors do not learn, then seditious people spring up, and that State will perish in no time. It is said in the Book of Poetry, "When such an overthrow of Zhou is being produced by Heaven, Be not ye so much at your ease!" " At your ease;" - that is, dilatory. And so dilatory may those officers be deemed, who serve their prince without righteousness, who take office and retire from it without regard to propriety, and who in their words disown the ways of the ancient kings. Therefore it is said, "To urge one's sovereign to difficult achievements may be called showing respect for him. To set before him what is good and repress his perversities may be called showing reverence for him. He who does not do these things, saying to himself, My sovereign is incompetent to this, may be said to play the thief with him."

所以說：「城牆不完整、攻守武器不多，這並不算國家的災難；田地未開墾、物資財寶未累積，這也不算國家的危害。」當上位者不遵守禮節，下位者不學習，那麼叛亂的奸民就會興起，國家滅亡的日子就不遠了。《詩經》上說：「當上天正在促使周朝覆滅之際，你們不要如此安逸怠惰啊！」所謂「安逸」，意思就是怠惰。那些侍奉君王卻不講道義、任職與離職都不合乎禮節、言談中否定先王之道的官員，就可以被看作是如此怠惰的人。所以說：「要求君王去完成艱鉅難辦的事業，這可叫做對他真正的尊重；向他陳述美善並遏止他的邪念，這可叫做對他真正的敬意。如果不這樣做，反而心想『我的君王做不到這點』，這就可以說是在賊害自己的君王。」

Mencius said, The compass and square produce perfect circles and squares. By the sages, the human relations are perfectly exhibited. He who as a sovereign would perfectly discharge the duties of a sovereign, and he who as a minister would perfectly discharge the duties of a minister, have only to imitate - the one Yao, and the other Shun. He who does not serve his sovereign as Shun served Yao, does not respect his sovereign; and he who does not rule his people as Yao ruled his, injures his people. Confucius said, "There are but two courses, which can be pursued, that of virtue and its opposite." A ruler who carries the oppression of his people to the highest pitch, will himself be slain, and his kingdom will perish. If one stop short of the highest pitch, his life will notwithstanding be in danger, and his kingdom will be weakened. He will be styled "The Dark," or "The Cruel," and though he may have filial sons and affectionate grandsons, they will not be able in a hundred generations to change the designation. This is what is intended in the words of the Book of Poetry, "The beacon of Yin is not remote, It is in the time of the (last) sovereign of Xia."

孟子說：「規和矩能畫出完美的圓與方；聖人則將人與人之間的倫理道德完美地展現出來。身為君王想要盡到君王的職責，身為臣子想要盡到臣子的職責，兩者都只要效法古人即可——君王效法堯，臣子效法舜。不用舜侍奉堯的方式來侍奉君王的人，就是不尊重君王；不用堯治理百姓的方式來治理百姓的人，就是傷害百姓。孔子說：『人生可走的道路只有兩條，不是行仁德，就是行不仁。』殘害人民到了極點的君主，自己會被殺，國家也會滅亡；即使沒到極點，他的生命依然會陷入危險，國家也會遭到削弱。他會被冠上『幽』或『厲』的惡諡，縱使有孝順的兒子和慈愛的孫子，過了一百年也無法更改這個稱號。這就是《詩經》所說『殷商的借鏡並不遙遠，就在夏代最後一個君王的時代』的意思。」

Mencius said, It was by benevolence that the three dynasties gained the throne, and by not being benevolent that they lost it. It is by the same means that the decaying and flourishing, the preservation and perishing, of States are determined. If the sovereign be not benevolent, he cannot preserve the throne from passing from him. If the Head of a State be not benevolent, he cannot preserve his rule. If a high noble or great officer be not benevolent, he cannot preserve his ancestral temple. If a scholar or common man be not benevolent, be cannot preserve his four limbs. Now they hate death and ruin, and yet delight in being not benevolent - this is like hating to be drunk, and yet being strong to drink wine!

孟子說：「夏、商、周三代之所以能取得天下，是由於實行仁政；他們之所以失去天下，是由於不行仁政。國家之所以衰退與繁榮、存留與滅亡，道理也都是一樣的。如果天子不仁，就無法保住天下；如果諸侯不仁，就無法保住他的封國；如果卿大夫不仁，就無法保住他的宗廟；如果士人或平民不仁，連自己的四肢軀體都保全不住。現在人們討厭死亡與敗亡，卻又喜愛做不仁的事，這就像是討厭喝醉卻又勉強自己去喝酒一樣！」

Mencius said, 'If a man love others, and no responsive attachment is shown to him, let him turn inwards and examine his own benevolence. If he is trying to rule others, and his government is unsuccessful, let him turn inwards and examine his wisdom. If he treats others politely, and they do not return his politeness, let him turn inwards and examine his own feeling of respect. When we do not, by what we do, realise what we desire, we must turn inwards, and examine ourselves in every point. When a man's person is correct, the whole kingdom will turn to him with recognition and submission. It is said in the Book of Poetry, "Be always studious to be in harmony with the ordinances of God, And you will obtain much happiness."

孟子說：「如果一個人去愛別人，卻得不到別人相應的親近，就要回過頭來檢查自己的仁愛夠不夠；如果他在治理別人卻沒有治理好時，就要回過頭來檢查自己的智慧夠不夠；如果他以禮待人卻得不到對方的以禮相報，就要回過頭來檢查自己的恭敬夠不夠。凡是我們的作為達不到內心所期望的結果時，都必須回過頭來，在各個方面自我檢討。當一個人的自身行為端正了，天下的人就會歸順並認同他。《詩經》上說：『時常努力使自己的行為合乎天命，就會得到許多的幸福。』」

Mencius said, People have this common saying, "The kingdom, the State, the family." The root of the kingdom is in the State. The root of the State is in the family. The root of the family is in the person of its Head.

孟子說：「人們常有一句俗語說：『天下國家』。天下的根本在於諸侯國，國家的根本在於家族，而家族的根本則在於個人自身的修養。」

Mencius said, The administration of government is not difficult - it lies in not offending the great families. He whom the great families affect, will be affected by the whole State; and he whom any one State affects, will be affected by the whole kingdom. When this is the case, such an one's virtue and teachings will spread over all within the four seas like the rush of water.

孟子說：「治理政事並不困難——關鍵在於不要得罪世家大族。大族所喜愛推崇的人，全國的人民也會跟著喜愛推崇；全國所喜愛推崇的人，天下的人民也都會跟著喜愛推崇。到了這個地步，這個人的品德與教化就會像滔滔江水一樣，普及到四海之內。」

Mencius said, When right government prevails in the kingdom, princes of little virtue are submissive to those of great, and those of little worth to those of great. When bad government prevails in the kingdom, princes of small power are submissive to those of great, and the weak to the strong. Both these cases are the rule of Heaven. They who accord with Heaven are preserved, and they who rebel against Heaven perish. The duke Jing of Qi said, "Not to be able to command others, and at the same time to refuse to receive their commands, is to cut one's self off from all intercourse with others." His tears flowed forth while he gave his daughter to be married to the prince of Wu.

孟子說：「天下有道的時候，品德小的人服從品德大的人，才能小的人服從才能大的人；天下無道的時候，小國服從大國，弱國服從強國。這兩種情況，都是自然的規律。順應天理的人存活，違背天理的人滅亡。齊景公說：『既不能發號施令給別人，又拒絕接受別人的命令，這就是斷絕與外界的一切往來。』他一邊流著眼淚，一邊把女兒嫁給吳國的國君。

Now the small States imitate the large, and yet are ashamed to receive their commands. This is like a scholar's being ashamed to receive the commands of his master. For a prince who is ashamed of this, the best plan is to imitate king Wen. Let one imitate king Wen, and in five years, if his State be large, or in seven years, if it be small, he will be sure to give laws to the kingdom. It is said in the Book of Poetry, "The descendants of the sovereigns of the Shang dynasty, Are in number more than hundreds of thousands, But, God having passed His decree, They are all submissive to Zhou. They are submissive to Zhou, Because the decree of Heaven is not unchanging. The officers of Yin, admirable and alert, Pour out the libations, and assist in the capital of Zhou." Confucius said, "As against so benevolent a sovereign, they could not be deemed a multitude." Thus, if the prince of a state love benevolence, he will have no opponent in all the kingdom. Now they wish to have no opponent in all the kingdom, but they do not seek to attain this by being benevolent. This is like a man laying hold of a heated substance, and not having first dipped it in water. It is said in the Book of Poetry, "Who can take up a heated substance, Without first dipping it (in water)?"

現在小國效仿大國，卻又以接受大國的命令為恥，這就像是一個學生以接受老師的教導為恥一樣。國君如果以此為恥，最好的辦法就是效法周文王。只要效法周文王，如果是大國，五年之內；如果是小國，七年之內，一定能夠在天下施行仁政。《詩經》上說：『商朝的子孫，數量超過十萬；但上帝下了命令，他們全都歸順了周朝。他們歸順周朝，是因為天命不是一成不變的。殷商的官員聰明敏捷，到京城來參與祭祀。』孔子說：『面對如此仁慈的君王，敵人是無法被視為人數眾多的。』因此，如果一個國家的君王喜愛仁德，他在天下就沒有敵手。現在的人們想要在天下沒有敵手，卻不透過行仁德來達到這個目的，這就像一個人用手去抓燒燙的物體，卻沒有先把它在水中浸濕一樣。《詩經》上說：『誰能夠拿起燒燙的東西，卻不先把它用水浸濕呢？』」

Mencius said, 'How is it possible to speak with those princes who are not benevolent? Their perils they count safety, their calamities they count profitable, and they have pleasure in the things by which they perish. If it were possible to talk with them who so violate benevolence, how could we have such destruction of States and ruin of Families? There was a boy singing, "When the water of the Cang Lang is clear, It does to wash the strings of my cap; When the water of the Cang Lang is muddy, It does to wash my feet." Confucius said, "Hear what he sings, my children. When clear, then he will wash his cap-strings; and when muddy, he will wash his feet with it. This different application is brought by the water on itself." A man must first despise himself, and then others will despise him. A family must first destroy itself, and then others will destroy it. A State must first smite itself, and then others will smite it. This is illustrated in the passage of the Tai Jia, "When Heaven sends down calamities, it is still possible to escape them. When we occasion the calamities ourselves, it is not possible any longer to live."

孟子說：「怎麼可能與那些不仁的君王談論道理呢？他們把危險當作安全，把災禍當作利益，並且對導致自己滅亡的事物感到快樂。如果可以跟這些違背仁德的人談論政事，又怎麼會發生國家毀滅、家族破產的事呢？曾有個小孩子唱歌說：『滄浪的水清啊，可以用來洗我的帽帶；滄浪的水濁啊，可以用來洗我的腳。』孔子說：『孩子們聽著！水清就拿來洗帽帶，水濁就拿來洗腳，這都是水自己招致的啊。』一個人必定是先自取其辱，然後別人才會侮辱他；一個家庭必定是先自我毀壞，然後別人才會毀壞它；一個國家必定是先自我伐害，然後別人才會伐害它。《太甲》上說：『上天降下的災難，還可以逃避；自己作孽造成的災難，是活不成的。』說的就是這個道理。」

Mencius said, Jie and Zhou's losing the throne, arose from their losing the people, and to lose the people means to lose their hearts. There is a way to get the kingdom: get the people, and the kingdom is got. There is a way to get the people: get their hearts, and the people are got. There is a way to get their hearts: it is simply to collect for them what they like, and not to lay on them what they dislike. The people turn to a benevolent rule as water flows downwards, and as wild beasts fly to the wilderness. Accordingly, as the otter aids the deep waters, driving the fish into them, and the hawk aids the thickets, driving the little birds to them, so Jie and Zhou aided Tang and Wu, driving the people to them. If among the present rulers of the kingdom, there were one who loved benevolence, all the other princes would aid him, by driving the people to him. Although he wished not to become sovereign, he could not avoid becoming so. The case of one of the present princes wishing to become sovereign is like the having to seek for mugwort three years old, to cure a seven years' sickness. If it have not been kept in store, the patient may all his life not get it. If the princes do not set their wills on benevolence, all their days will be in sorrow and disgrace, and they will be involved in death and ruin. This is illustrated by what is said in the Book of Poetry, "How otherwise can you improve the kingdom? You will only with it go to ruin."

孟子說：「夏桀與商紂失去天下，是由於失去民心；失去民心，也就是失去了人民的擁戴。取得天下是有辦法的：得到人民，就能得到天下；得到人民是有辦法的：得到民心，就能得到人民；得到民心是有辦法的：把人民喜歡的替他們聚積起來，把人民厭惡的不要強加在他們身上罷了。人民歸順仁政，就像水往低處流、野獸奔向山林一樣。因此，水獺幫深水驅趕魚群，鸇鳥幫樹林驅趕小鳥，夏桀與商紂則是幫商湯與周武王把人民驅趕過去。現在天下的君王如果有喜愛仁德的，那麼諸侯們都會幫他把人民驅趕過來。他雖然不想統治天下，也辦不到了。現在的君王如果想統治天下，就像得了七年的慢性病，臨時才去尋找三年陳舊的艾草來治病一樣。平常如果沒有儲藏，一輩子也找不到了。諸侯們如果不把心思放在仁德上，終身都會在憂愁與恥辱中度過，並陷入死亡與敗亡的境地。《詩經》上說『怎能把國家治理好，只會一同走向滅亡』，說的就是這個意思。」

Mencius said, With those who do violence to themselves, it is impossible to speak. With those who throw themselves away, it is impossible to do anything. To disown in his conversation propriety and righteousness, is what we mean by doing violence to one's self. To say "I am not able to dwell in benevolence or pursue the path of righteousness," is what we mean by throwing one's self away. Benevolence is the tranquil habitation of man, and righteousness is his straight path. Alas for them, who leave the tranquil dwelling empty and do not reside in it, and who abandon the right path and do not pursue it?

孟子說：「自己摧殘自己的人，無法跟他談話；自己放棄自己的人，無法跟他有所作為。言談中否定禮義，這叫做自己摧殘自己；口口聲聲說『我不能安居於仁德、不能遵循道義』，這叫做自己放棄自己。仁德是人安適的住所，道義是人平坦的正路。可悲啊！那些空著安適的住所不住、卻要放棄正路而不走的人。」

Mencius said, The path of duty lies in what is near, and men seek for it in what is remote. The work of duty lies in what is easy, and men seek for it in what is difficult. If each man would love his parents and show the due respect to his elders, the whole land would enjoy tranquillity.

孟子說：「當行的大道就在眼前，人們卻偏要到遠處去尋求；應做的事情本來很容易，人們卻偏要到難處去尋求。如果每個人都能親愛自己的父母、尊敬自己的長輩，天下自然就會安定了。」

Mencius said, When those occupying inferior situations do not obtain the confidence of the sovereign, they cannot succeed in governing the people. There is a way to obtain the confidence of the sovereign: if one is not trusted by his friends, he will not obtain the confidence of his sovereign. There is a way of being trusted by one's friends: if one do not serve his parents so as to make them pleased, he will not be trusted by his friends. There is a way to make one's parents pleased: if one, on turning his thoughts inwards, finds a want of sincerity, he will not give pleasure to his parents. There is a way to the attainment of sincerity in one's self: if a man do not understand what is good, he will not attain sincerity in himself. Therefore, sincerity is the way of Heaven. To think how to be sincere is the way of man. Never has there been one possessed of complete sincerity, who did not move others. Never has there been one who had not sincerity who was able to move others.

孟子說：「處在下位的人如果得不到上位者的信任，就無法治理好百姓。要獲得上位者的信任是有辦法的：如果得不到朋友的信任，就無法獲得上位者的信任；要獲得朋友的信任是有辦法的：如果侍奉父母不能使他們高興，就無法得到朋友的信任；要使父母高興是有辦法的：自我反省時發現自己不夠真誠，就無法使父母高興；要讓自身達到真誠是有辦法的：如果不明白什麼是善，就無法使自身真誠。所以，真誠是天道；思考如何真誠，是人道。從來沒有極度真誠卻不能感動別人的；也從來沒有不真誠而能感動別人的。」

Mencius said, Bo Yi, that he might avoid Zhou, was dwelling on the coast of the northern sea. When he heard of the rise of king Wen, he roused himself, and said, "Why should I not go and follow him? I have heard that the chief of the West knows well how to nourish the old." Tai Gong, that he might avoid Zhou, was dwelling on the coast of the eastern sea. When he heard of the rise of king Wen, he roused himself, and said, "Why should I not go and follow him? I have heard that the chief of the West knows well how to nourish the old." Those two old men were the greatest old men of the kingdom. When they came to follow king Wen, it was the fathers of the kingdom coming to follow him. When the fathers of the kingdom joined him, how could the sons go to any other? Were any of the princes to practise the government of king Wen, within seven years he would be sure to be giving laws to the kingdom.

孟子說：「伯夷為了躲避紂王，住在北海的海濱。當他聽說周文王興起時，振作起來說：『我為什麼不去歸順他呢？我聽說西伯（文王）很懂得奉養老人。』太公為了躲避紂王，住在東海的海濱。當他聽說周文王興起時，振作起來說：『我為什麼不去歸順他呢？我聽說西伯很懂得奉養老人。』這兩位老人是天下最受尊敬的老人，他們來歸順文王，這就等於天下所有的父親都來歸順了。天下父親都歸順了，他們的兒子還能到哪裡去呢？如果有哪位諸侯實行周文王的政事，不出七年，一定能在天下建立政權。」

Mencius said, Qiu acted as chief officer to the head of the Ji family, whose evil ways he was unable to change, while he exacted from the people double the grain formerly paid. Confucius said, "He is no disciple of mine. Little children, beat the drum and assail him." Looking at the subject from this case, we perceive that when a prince was not practising benevolent government, all his ministers who enriched him were rejected by Confucius - how much more would he have rejected those who are vehement to fight for their prince! When contentions about territory are the ground on which they fight, they slaughter men till the fields are fields of dead bodies. When some struggle for a city is the ground on which they fight, they slaughter men till the city is filled with them. This is what is called "leading on the land to devour human flesh." Death is not enough for such a crime. Therefore, those who are skilful to fight should suffer the highest punishment. Next to them should be punished those who unite some princes in leagues against others; and next to them, those who take in grassy commons, imposing the cultivation of the ground on the people.

孟子說：「冉求擔任季孫氏的家相，無法改變季孫氏的惡政，反而幫忙向百姓徵收比平時多一倍的租稅。孔子說：『他不是我的學生，小子們，敲起鼓來攻擊他吧！』由此看來，國君如果不實行仁政，凡是幫忙讓國君聚斂財富的大臣，都是被孔子所唾棄的，更何況是那些賣力為國君發動殘酷戰爭的人呢？為了爭奪土地而戰，殺得死人遍野；為了爭奪城池而戰，殺得城中滿是屍體。這就叫做率領土地來吃人肉，罪惡深重，死不足惜。因此，善於打仗的將領應該判處最重的刑罰，其次是連結諸侯發動侵略的謀士，再次則是強佔荒地、加重人民勞役的政客。」

Mencius said, Of all the parts of a man's body there is none more excellent than the pupil of the eye. The pupil cannot be used to hide a man's wickedness. If within the breast all be correct, the pupil is bright. If within the breast all be not correct, the pupil is dull. Listen to a man's words and look at the pupil of his eye. How can a man conceal his character?

孟子說：「人的身體部位中，沒有比黑眼珠更明察正直的了。黑眼珠無法掩飾一個人的邪惡。如果心中光明正大，黑眼珠就明亮；如果心中不正，黑眼珠就昏暗呆滯。聽一個人說話，又觀察他的眼睛，這個人的本質怎麼隱藏得了呢？」

Mencius said, The respectful do not despise others. The economical do not plunder others. The prince who treats men with despite and plunders them, is only afraid that they may not prove obedient to him - how can he be regarded as respectful or economical? How can respectfulness and economy be made out of tones of the voice, and a smiling manner?

孟子說：「真正恭敬的人不會看輕別人，真正節儉的人不會掠奪別人。那種對人傲慢又掠奪人民財物的國君，只怕人民不聽從自己，這哪裡算得上是恭敬或節儉？恭敬與節儉怎麼可能是靠說話的語調和滿臉堆笑裝得出來的呢？」

Chun Yu Kun said, Is it the rule that males and females shall not allow their hands to touch in giving or receiving anything?' Mencius replied, 'It is the rule.' Kun asked, 'If a man's sister-in-law be drowning, shall he rescue her with his hand?' Mencius said, 'He who would not so rescue the drowning woman is a wolf. For males and females not to allow their hands to touch in giving and receiving is the general rule; when a sister-in-law is drowning, to rescue her with the hand is a peculiar exigency.' Kun said, 'The whole kingdom is drowning. How strange it is that you will not rescue it!' Mencius answered, 'A drowning kingdom must be rescued with right principles, as a drowning sister-in-law has to be rescued with the hand. Do you wish me to rescue the kingdom with my hand?

淳于髡問：「男女之間遞交物品不親手接觸，這是禮節嗎？」孟子回答：「這是禮節。」淳于髡又問：「如果嫂子落水了，要用手去拉她嗎？」孟子說：「不援救落水嫂子的人，簡直是豺狼。男女遞交物品不親手接觸，這是常規；而嫂子落水時用手去拉她，則是因應特殊情況的權宜之變。」淳于髡說：「現在全天下的人都落水了，您為什麼不去拯救呢？」孟子回答：「天下落水，要用正道去拯救；嫂子落水，要用手去拉。難道您希望我用一隻手去拯救天下嗎？」

Gong Sun Chou said, Why is it that the superior man does not himself teach his son?' Mencius replied, 'The circumstances of the case forbid its being done. The teacher must inculcate what is correct. When he inculcates what is correct, and his lessons are not practised, he follows them up with being angry. When he follows them up with being angry, then, contrary to what should be, he is offended with his son. At the same time, the pupil says, "My master inculcates on me what is correct, and he himself does not proceed in a correct path." The result of this is, that father and son are offended with each other. When father and son come to be offended with each other, the case is evil. The ancients exchanged sons, and one taught the son of another. Between father and son, there should be no reproving admonitions to what is good. Such reproofs lead to alienation, and than alienation there is nothing more inauspicious.

公孫丑問：「君子不親自教導自己的兒子，這是為什麼？」孟子回答：「客觀形勢不允許這樣做。老師教導學生必須合乎正道；如果教導了正道而兒子沒有做到，父親就會動怒；動怒了，就會產生怨恨。兒子則會想：『父親用正道教我，但父親自己未必做到了正道。』這樣父子就會互相怨恨。父子互相怨恨，關係就壞了。所以古代的人互換兒子來教導。父親與兒子之間不直接責求行善，因為責求行善會導致父子疏遠，而沒有比父子疏遠更不吉利的事了。」

Mencius said, Of services, which is the greatest? The service of parents is the greatest. Of charges, which is the greatest ? The charge of one's self is the greatest. That those who do not fail to keep themselves are able to serve their parents is what I have heard. But I have never heard of any, who, having failed to keep themselves, were able notwithstanding to serve their parents. There are many services, but the service of parents is the root of all others. There are many charges, but the charge of one's self is the root of all others. The philosopher Zeng, in nourishing Zeng Xi, was always sure to have wine and flesh provided. And when they were being removed, he would ask respectfully to whom he should give what was left. If his father asked whether there was anything left, he was sure to say, "There is." After the death of Zeng Xi, when Zeng Yuan came to nourish Zengzi, he was always sure to have wine and flesh provided. But when the things were being removed, he did not ask to whom he should give what was left, and if his father asked whether there was anything left, he would answer "No;" - intending to bring them in again. This was what is called "nourishing the mouth and body." We may call Zengzi's practice "nourishing the will." To serve one's parents as Zengzi served his, may be accepted as filial piety.

孟子說：「各種侍奉中，哪一個最大？侍奉父母最大。各種責任中，哪一個最大？對自身的修養與護衛最大。沒有失去自身品德而能侍奉好父母的，我聽說過；自身品德敗壞卻能侍奉好父母的，我從未聽說過。要侍奉的事很多，侍奉父母是根本；要負責的事很多，修養自身是根本。曾子奉養他的父親曾皙時，必定準備酒肉；撤席時，一定恭敬地請示要把剩下的肉送給誰；父親問有沒有剩酒肉，他一定回答『有』。曾皙死後，曾元奉養曾子，也必定準備酒肉；但撤席時，卻不請示剩餘的酒肉給誰，父親問有沒有剩的，他回答『沒有』，心裡打算留著下次再拿出來。這就叫做只養口體（物質生活）。而像曾子那樣，就可以叫做養志（滿足父母的心意）。像曾子那樣侍奉父母，才可稱得上是真正的孝順。」

Mencius said, It is not enough to remonstrate with a sovereign on account of the mal-employment of ministers, nor to blame errors of government. It is only the great man who can rectify what is wrong in the sovereign's mind. Let the prince be benevolent, and all his acts will be benevolent. Let the prince be righteous, and all his acts will be righteous. Let the prince be correct, and everything will be correct. Once rectify the ruler, and the kingdom will be firmly settled.

孟子說：「規勸君主不要任用不當的大臣，或者指責政令的錯誤，這些都還不夠。只有偉大的人物才能夠導正君王心中的偏差。國君仁愛，沒有哪一件事不仁愛；國君道義，沒有哪一件事不道義；國君端正，沒有哪一件事不端正。只要端正了君王的心思，國家就能夠安穩安定了。」

Mencius said, There are cases of praise which could not be expected, and of reproach when the parties have been seeking to be perfect.

孟子說：「有時候會得到意料之外的讚譽，有時候卻因力求完美而遭到嚴厲的批評。」

Mencius said, Men's being ready with their tongues arises simply from their not having been reproved.

孟子說：「人之所以隨便發表言論、口無遮攔，單純是因為沒有遭受過嚴厲的斥責與教訓罷了。」

Mencius said, The evil of men is that they like to be teachers of others.

孟子說：「人的最大毛病，就是喜歡好為人師，到處教導別人。」

The disciple Yue Zheng went in the train of Zi Ao to Qi. He came to see Mencius, who said to him, 'Are you also come to see me?' Yue Zheng replied, 'Master, why do you speak such words?' 'How many days have you been here?' asked Mencius. 'I came yesterday.' 'Yesterday! Is it not with reason then that I thus speak?' 'My lodging-house was not arranged.' 'Have you heard that a scholar's lodging-house must be arranged before he visit his elder?' Yue Zheng said, 'I have done wrong.

學生樂正子跟隨子敖來到齊國，並去拜見孟子。孟子對他說：「你也來見我嗎？」樂正子說：「先生為什麼說這樣的話？」孟子問：「你來幾天了？」回答說：「昨天來的。」孟子說：「昨天來的，那我說這樣的話不是很合理嗎？」樂正子說：「我的住所還沒安頓好。」孟子說：「你聽說過嗎？住所安頓好之後，才可以去拜見長輩。」樂正子說：「我確實做錯了。」

Mencius, addressing the disciple Yue Zheng, said to him, 'Your coming here in the train of Zi Ao was only because of the food and the drink. I could not have thought that you, having learned the doctrine of the ancients, would have acted with a view to eating and drinking.

孟子對樂正子說：「你跟隨著子敖來到齊國，單純是為了混口飯吃罷了。我真沒想到你學了古代的道統，竟然是為了追求飲食溫飽而來。」

Mencius said, 'There are three things which are unfilial, and to have no posterity is the greatest of them. Shun married without informing his parents because of this, lest he should have no posterity. Superior men consider that his doing so was the same as if he had informed them.

孟子說：「不孝順的行為有三種，其中沒有後代是最大宗的。舜結婚沒有稟告父母，就是為了怕沒有後代。君子認為他這樣做，就等於是已經稟告過父母一樣。」

Mencius said, The richest fruit of benevolence is this: the service of one's parents. The richest fruit of righteousness is this: the obeying one's elder brothers. The richest fruit of wisdom is this: the knowing those two things, and not departing from them. The richest fruit of propriety is this: the ordering and adorning those two things. The richest fruit of music is this: the rejoicing in those two things. When they are rejoiced in, they grow. Growing, how can they be repressed? When they come to this state that they cannot be repressed, then unconsciously the feet begin to dance and the hands to move.

孟子說：「仁的實質表現，就是侍奉父母；義的實質表現，就是順從兄長；智的實質表現，就是明白這兩點且不背離；禮的實質表現，就是調節和文飾這兩點；樂的實質表現，就是對這兩點感到快樂。對這兩點感到快樂，仁義之心就會生長；一旦生長了，怎麼壓抑得住？當壓抑不住時，就會不知不覺地手舞足蹈起來。」

Mencius said, Suppose the case of the whole kingdom turning in great delight to an individual to submit to him. To regard the whole kingdom thus turning to him in great delight but as a bundle of grass - only Shun was capable of this. He considered that if one could not get the hearts of his parents he could not be considered a man, and that if he could not get to an entire accord with his parents, he could not be considered a son. By Shun's completely fulfilling everything by which a parent could be served, Gu Sou was brought to find delight in what was good. When Gu Sou was brought to find that delight, the whole kingdom was transformed. When Gu Sou was brought to find that delight, all fathers and sons in the kingdom were established in their respective duties. This is called great filial piety.

孟子說：「假設全天下的人都歡欣鼓悅地歸順某個人，而他看待天下人的歸順就像對待一捆雜草一樣輕描淡寫，只有舜能夠做到這一點。他認為如果得不到父母的心，就不能算是一個真正的人；如果不能和父母融洽相處，就不能算是一個真正的兒子。舜克盡了侍奉父母的道義，使得盲叟（舜父）轉而喜愛美善。當盲叟轉而喜愛美善時，全天下的人都被感化了；當盲叟轉而喜愛美善時，天下所有的父子關係也就都有了準則。這就叫做真正的大孝。」

NX

摘要

早期的 Unigraphics（UG）至中期的 I-DEAS、中後期的 NX，再至 2026 年 Designcenter 的演進，並非單純的產品改名或使用者介面更新，而是一條由數值控制（Numerical Control, NC）、電腦輔助製造（Computer-Aided Manufacturing, CAM）、電腦輔助設計（Computer-Aided Design, CAD）、電腦輔助工程（Computer-Aided Engineering, CAE）、產品資料管理（Product Data Management, PDM）逐步整合至產品生命週期管理（Product Lifecycle Management, PLM），並進一步向數位主線（Digital Thread）、雲端工程（Cloud Engineering）與人工智慧輔助工程（AI-assisted Engineering）延伸的技術發展歷程。

此一技術血統可追溯至 1960 年代 United Computing 所發展之 APT/UNIAPT 技術，1970 年代形成 UNI-GRAPHICS，1976 年進入 McDonnell Douglas 體系；1990 年代進入 EDS 時代；2001 年 EDS 將 UGS 與 SDRC 納入同一 PLM 組織，促成 Unigraphics 與 I-DEAS 技術整合；2002 年正式推出 NX；2007 年 Siemens 收購 UGS；2019 年導入 Continuous Release；2022 年改採年份與月份作為版本標識；2025 年將 NX 納入 Designcenter 品牌；2026 年 6 月進一步以 Designcenter 2606 作為統一產品名稱。

從技術史角度觀察，這條演進路徑的核心並非「CAD 功能越來越多」，而是產品資訊的數位化邊界持續擴張：由幾何描述擴張至產品結構，由產品結構擴張至工程分析與製造，再由工程資料擴張至整個產品生命週期，最終形成設計、模擬、製造、資料管理、協作、雲端與 AI 相互連接的工程平台。

一、研究範圍與歷史定位

現代 Designcenter 的技術來源具有多重企業與產品血統，其中最重要者包括 United Computing、Unigraphics、McDonnell Douglas、EDS、UGS、SDRC、I-DEAS 以及 Siemens。

Unigraphics 是主要產品技術主幹之一；I-DEAS 則構成另一條重要 CAD/CAE/PDM 技術支流；兩者在 EDS/UGS 體系下開始整合，最終形成 NX；NX 再進入 Siemens 工業軟體體系，並逐漸由單一 CAD/CAM 產品演化成更大範圍的工程平台。

Designcenter CAD 軟體的產品歷史可追溯至 1975 年 Unigraphics；2002 年 EDS 將 UGS 的 Unigraphics 與 SDRC 的 I-DEAS 整合成 NX；2007 年 Siemens 收購 UGS；2019 年導入 NX Continuous Release；2022 年採用 YYYYMM 型版本命名；2025 年進入 Designcenter NX 品牌；2026 年 6 月則進一步更名為 Designcenter。

二、第一階段：NC 與 APT——CAD 的前置技術背景

2.1 從「繪圖」到「描述製造」

現今 CAD 的概念通常以幾何建模為起點，但從 Unigraphics 的歷史而言，更早的技術根源實際上與 NC 加工密切相關。

1963 年 United Computing 成立，1969 年推出 UNIAPT。UNIAPT 是以 APT（Automatically Programmed Tools）為基礎的數值控制程式技術，試圖以數位方式描述零件幾何與加工過程，並將工程資訊轉換為機器可執行的加工資訊。此一發展重點對後續 Unigraphics 產生根本性影響，也是 UG 在 CAM 專業領域一直佔有重要地位的原因。

1973 年，United Computing 取得 ADAM 程式碼並將其移植至早期 16-bit minicomputer，加入 Tektronix 圖形顯示及選單式操作介面，形成 UNI-GRAPHICS。

三、第二階段：Unigraphics——從 NC/CAM 走向完整 CAD/CAM

3.1 McDonnell Douglas 時期

1976 年 United Computing 被 McDonnell Douglas 收購，成為 McAuto 體系的一部分。此一企業環境具有大型航空製造業的典型特徵，包括複雜曲面、大型組件、精密加工、工程變更及長產品生命週期等需求。

此時 Unigraphics 的技術發展逐漸由 NC/CAM 擴展至完整 CAD/CAM 環境。

其功能範圍逐漸涵蓋：

    線框幾何；
    曲面建模；
    實體建模；
    工程圖；
    組合件；
    特徵建模；
    數值控制；
    加工路徑；
    工程資料。

四、第三階段：EDS——CAD 開始進入產品資料管理

1991 年 EDS 取得 McDonnell Douglas 的商業電腦服務業務；1996 年 Unigraphics 已經可以在 Microsoft Windows NT 環境執行。

截至 1990 年代真正重要的產業變化並不是作業系統由 Unix 轉向 Windows，而是製造業開始面對更嚴重的產品資訊管理問題。

大型產品的數位資料開始包括：

    零件；
    組合件；
    BOM；
    工程圖；
    規格；
    版本；
    工程變更；
    製造資訊；
    模擬資料；
    文件；
    品質資訊。

促使 CAD 在協同產品開發的過程中逐漸從「如何建立幾何？」轉變成「如何管理產品的數位資訊？」。

這便是 PDM 向 PLM 發展的重要背景。

五、第四階段：SDRC 與 I-DEAS——另一條重要技術支流

5.1 I-DEAS 的歷史地位

在 Unigraphics 發展的同時，另一個極具影響力的工程軟體體系是 SDRC 的 I-DEAS。

I-DEAS 在 CAD、CAE、工程分析以及產品資料管理方面具有深厚技術基礎。

因此，2001 年 EDS 將 UGS 與 SDRC 納入同一企業體系，將兩個成熟工程軟體技術體系加以整合。

當時 SDRC 的產品包括 I-DEAS 與 Metaphase，而 UGS 則擁有 Unigraphics 與 I-Man 等技術。此一整合最終形成 NX 與 Teamcenter。

六、2002 年：NX——New Generation

2002 年 EDS PLM Solutions 發布 Unigraphics NX。隱含所推出的套件為 New Generation of Unigraphics。其核心任務是將兩個成熟 CAD/CAE/CAM 技術體系逐步整合成共同的產品架構。

當時 NX 整合的內容包括：

    幾何資料；
    拓撲資料；
    Feature history；
    Parent-child dependency；
    Parametric relations；
    Assembly structure；
    Drawing；
    PMI；
    CAE model；
    CAM data；
    PDM metadata；
    Legacy data migration。

八、NX3 與 NX5：技術整合逐漸成熟

2004 年 NX3 推出。但一直到 NX5 時期才完全將 Unigraphics 與 I-DEAS 的產品技術整合進共同環境；同時開始在此基礎上發展直接建模、大型資料集處理、設計審查以及協同工程等新能力。

在 NX3 中可明顯看出 Unigraphics 的傳統 Feature、Part Navigator、Associative Modeling、Expression、Assembly 等概念，同時又開始呈現後來 NX 所發展的更大範圍工程架構。

九、Synchronous Technology：參數歷史與直接建模的融合

NX 後續發展中，一項具有長期影響的技術是 2008 年在 NX6 中推出的 Synchronous Technology。

傳統參數式 CAD 的核心思想是：

Feature → History → Dependency → Regeneration。

例如：

Sketch → Extrude → Hole → Edge Blend → Pattern。

此種架構對設計意圖管理非常有效，但對既有模型修改、外部 CAD 資料以及缺乏原始 Feature history 的幾何資料而言，存在一定限制。

Synchronous Technology 的重要性在於，它將直接幾何操作與設計意圖結合，使模型修改不必完全依賴傳統歷史樹。

這使 NX 的建模哲學逐漸從單一：

History-based Parametric Modeling

發展成：

Parametric + Direct + Synchronous Modeling。

其結果並非取消 Feature-based modeling，而是增加另一種工程修改方式。

對大型製造業而言，此種雙模式非常重要，因為實際產品資料通常同時包含：

原生參數模型、Legacy model、Imported STEP/IGES、供應商模型、逆向工程模型以及經過多次工程變更的歷史資料。

十、NX 從 CAD 軟體轉變為 Product Engineering Platform

當 NX 的能力逐漸涵蓋：

CAD、CAM、CAE、Assembly、Product Definition、Manufacturing、Simulation、Knowledge-based Engineering 等領域後，以「CAD software」描述 NX 已逐漸不足。

更適合的概念是：

Product Engineering Platform。

此時工程資訊的核心關係逐漸變成：

Design → Simulation → Manufacturing → Product Data → Lifecycle

而不再只是：

Sketch → Solid → Drawing。

這種轉變與 PLM 的發展密切相關。

十一、Teamcenter 與 NX：從 CAD 資料走向 PLM

Unigraphics、I-DEAS 等技術整合的另一個重要結果，就是 Teamcenter。

如前所述，SDRC 的 Metaphase/I-DEAS 與 UGS 的 I-Man/Unigraphics 技術整合，形成 NX 與 Teamcenter 的基礎。

其基本架構為：

NX：建立與修改產品工程資訊。

Teamcenter：管理產品資訊及其生命週期。

這兩者形成互補關係。

例如完整的產品資料除了零件檔案外，其隨後的產品資訊還包括

零件 → 組件 → BOM → 文件 → 規格 → 工程變更 → 模擬 → 製造 → 品質 → 服務。

因此，PLM 的核心問題已經從「檔案管理」提升為：

Product Structure Management + Configuration Management + Lifecycle Management。

十二、2007 年：Siemens 收購 UGS

2007 年 Siemens AG 收購 UGS。

由於 Siemens 本身具有龐大的工業自動化、機械、電氣、製造與工程業務。因此 UGS 的 CAD/CAM/PLM 技術進入 Siemens 後，具備與更廣泛工業軟體生態整合的條件。之後產品在業界普遍被稱為 Siemens NX。

此一階段的重要變化，是 NX 不再只是 CAD/CAM 產品線，而逐漸成為 Siemens Digital Industries Software 工程軟體體系的重要核心。

十三、NX、Simcenter、Teamcenter 與數位工程

隨著 Siemens 工業軟體架構成熟，產品工程逐漸形成多層次結構。其中 NX 主要處理設計與製造工程。而另一產品線 Simcenter 則逐漸承接更廣泛的 CAE、Simulation 與 Test 能力。Teamcenter 則負責產品資料、產品結構及生命週期管理。

因此整體概念逐漸由：

CAD/CAM

轉向：

CAD + CAE + CAM + PDM + PLM。

進一步則形成：

Design + Simulation + Manufacturing + Lifecycle。

這也是 PLM 產業從「管理 CAD file」進化至「管理產品數位模型」的重要階段。

十四、2019 年：Continuous Release

2019 年 Siemens PLM Software 對 NX 引入 Continuous Release。

傳統 CAD 的產品生命週期通常採：

NX 3 → NX 4 → NX 5 → … → NX 12。

此種模式具有明確版本邊界，但升級成本也較高。

Continuous Release 則改為持續更新。

Siemens 於 2019 年導入 Continuous Release，更新週期為每六個月；2022 年 6 月開始採用年份與月份命名，例如 NX 2206。

這代表 CAD 軟體開始由：

Major Version Product

轉變為：

Continuously Evolving Engineering Platform。

其本質與雲端軟體的生命週期管理方式更加接近。

十五、NX 2206：版本號開始具有時間意義

NX 2206 的「2206」不是傳統意義上的第 22 代版本。

其含義為：

2022 年 06 月 Release。

此模式的重要性在於，版本號本身開始反映軟體生命週期，而不是產品世代。

此種方式有利於：

    IT deployment；
    Release management；
    CAD data compatibility planning；
    Enterprise software governance；
    Cloud/desktop synchronization。

十六、2025 年：Designcenter NX

2025 年 1 月，Siemens 將 NX 納入 Designcenter 品牌，產品名稱改為 Designcenter NX。

同時形成 Designcenter product design and engineering suite，包含 Designcenter NX 與 Designcenter Solid Edge。

此一品牌轉變具有明確的架構意義。

「NX」代表的是一個成熟工程軟體產品與技術血統。

「Designcenter」則代表更高層級的產品設計與工程平台。

其中 NX 是技術產品名稱；Designcenter 開始成為平台級品牌。

十七、2026 年：Designcenter 2606

2026 年 6 月，Designcenter NX 進一步更名為 Designcenter。第一個以此名稱發行的版本為 Designcenter 2606。

十八、從 Desktop CAD 到 Desktop + Cloud Engineering

2026 年的 Designcenter 發展方向進一步將傳統桌面工程軟體與雲端工程環境連接。套件架構成為:

Desktop Engineering + Cloud Engineering + PLM + Collaboration。

其原因在於高階 CAD/CAE/CAM 仍涉及：

    GPU 計算；
    CPU 計算；
    大型 Assembly；
    高階曲面；
    複雜 Feature regeneration；
    CAM toolpath；
    大型 simulation；
    本地資料；
    網路延遲；
    資料安全。

Cloud 版本的核心價值是希望讓產品資料、工程流程、協作與計算資源具有更高的可存取性與可擴展性。

十九、Digital Thread：PLM 的下一個階段

PLM 的早期目標主要是：

管理產品資料。

Digital Thread 的目標則進一步變成：

連接產品生命週期中的數位資訊。

例如：

Requirements
↓
System Architecture
↓
CAD
↓
CAE
↓
CAM
↓
Manufacturing
↓
Quality
↓
Service

若這些資料互相獨立，則產品生命週期會形成大量資訊斷點。

若資料可以保持關聯，則可以形成：

Digital Thread。

因此，Designcenter、Simcenter、Teamcenter 等產品之間的整合，本質上並不是簡單的軟體套裝，而是試圖建立產品數位主線。

二十、AI Engineering：CAD 的下一次抽象層提升

2020 年代後半段，AI 開始成為工程軟體的重要組成。

傳統 CAD 的操作模式為：

Engineer Intent → Command → Geometry。

AI-assisted Engineering 則逐漸發展成：

Engineering Intent → AI Interpretation → Engineering Operation → Validation。

例如傳統操作需要工程師明確選取：

Feature、Face、Edge、Constraint、Parameter。

AI 系統則可能逐步理解：

設計需求、工程規範、歷史資料與目前建模情境。

Siemens 2026 年 Designcenter 發展方向已包含 AI-assisted design analysis、optimization、design generation 以及 Designcenter Copilot 等能力。

二十一、從 Feature-based CAD 到 Intent-based Engineering

若將 Designcenter 2026 歷經六十年的技術發展抽象化，可以看到 CAD 系統的抽象層逐漸提升。

早期：

Geometry

關注的是：

「這個點、線、面在哪裡？」

之後：

Solid Modeling

關注：

「這個零件是什麼形狀？」

再之後：

Feature-based Parametric Modeling

關注：

「這個零件如何建立？」

接著：

Knowledge-based Engineering

關注：

「這個零件為什麼這樣設計？」

再進一步：

PLM / Digital Thread

關注：

「這個零件在產品生命週期中扮演什麼角色？」

目前則逐漸走向：

AI-assisted Intent-based Engineering

其問題轉變為：

「產品需求如何轉換成可驗證的工程方案？」

這是從 CAD 到 Designcenter 最值得注意的技術演進。

二十二、Unigraphics、I-DEAS 與 NX 的真正技術關係

從工程軟體史的角度，可將其理解為三個不同階段。

Unigraphics 的核心歷史優勢在於：

NC/CAM + CAD + Manufacturing Engineering。

I-DEAS 的重要技術資產則集中於：

CAD + CAE + Engineering + PDM。

NX 則是：

Unigraphics 為主要產品主幹，融合 I-DEAS 等技術後形成的下一代 CAD/CAM/CAE 平台。

NX 的發展是以兩套系統的技術整合為核心，且這種大型 CAD 系統整合在當時的 CAD/CAM 工業史上具有高度特殊性。

二十五、結論

從 1960 年代 United Computing 的 NC/APT 技術，到 1970 年代 UNI-GRAPHICS；從 McDonnell Douglas 時代的 Unigraphics，到 EDS/UGS 時代；從 SDRC I-DEAS 與 Unigraphics 的整合，到 2002 年 NX 的建立；再經 Siemens 於 2007 年取得 UGS、2019 年 Continuous Release、2022 年時間型版本命名、2025 年 Designcenter NX，以及 2026 年 Designcenter 2606，整條技術演進可以視為一個持續提高「產品數位化抽象層級」的過程。

其最早期的核心問題是：

如何以電腦描述幾何與加工。

其後轉變為：

如何建立具有設計意圖的三維產品模型。

再進一步：

如何整合設計、分析與製造。

之後：

如何管理完整產品資料與生命週期。

而 2026 年的主要問題則逐漸轉變為：

如何使產品資料、工程流程、模擬、製造、協作、雲端與人工智慧形成連續的數位工程環境。

因此，從技術史觀點而言，「UG → NX → Designcenter」是 CAD 軟體由幾何工具逐步演化為產品工程基礎設施（Product Engineering Infrastructure） 的一個具代表性的案例。

其中最值得注意的歷史事實，是 Unigraphics 的製造工程血統、I-DEAS 的 CAD/CAE/PDM 技術、EDS/UGS 的 PLM 戰略，以及 Siemens 的工業數位化戰略，最終在 Designcenter 時代逐漸匯合。

總之 2026 年的 Designcenter 從早期 Unigraphics 套件，逐步將數十年間累積的 CAD、CAM、CAE、PDM、PLM、Digital Thread、Cloud Engineering 與 AI Engineering 等技術，重新置於一個更高層級產品工程架構之下，未來可望有更令人期待的發展。

/* --------------------------------------------------------------------------
 * 函式：report
 * 功能：檢查 UF 函式回傳值，若有錯誤則印出檔名、行號與錯誤訊息

/* --------------------------------------------------------------------------
 * 函式：prompt_for_three_numbers
 * 功能：彈出對話框讓使用者輸入三個數值（節圓直徑、齒數、齒寬）
 * 參數：
 *   prompt          - 對話框標題
 *   item1/item2/item3 - 三個輸入欄位標籤
 *   number1/2/3     - 輸入/輸出數值指標（有預設值）
 * 回傳：TRUE = 使用者按了 OK，FALSE = 取消
 * -------------------------------------------------------------------------- */
static logical prompt_for_three_numbers(char *prompt, char *item1, char *item2, char *item3,
                                        double *number1, double *number2, double *number3)
{
    int irc, resp;
    char menu[3][16];                           /* 三個欄位標籤 */
    double da[3];                               /* 暫存輸入值 */

    memset(menu, 0, sizeof(menu));              /* 清零 */
    strncpy(menu[0], item1, 15); menu[0][15] = '\0';  /* 複製標籤並確保結尾 null */
    strncpy(menu[1], item2, 15); menu[1][15] = '\0';
    strncpy(menu[2], item3, 15); menu[2][15] = '\0';

    da[0] = *number1;                           /* 帶入預設值 */
    da[1] = *number2;
    da[2] = *number3;

    /* uc1609：顯示三個數值輸入對話框 */
    resp = uc1609(prompt, menu, 3, da, &irc);

    if (resp == 3 || resp == 4)                 /* 3 或 4 表示使用者按了確定 */
    {
        *number1 = da[0];
        *number2 = da[1];
        *number3 = da[2];
        return TRUE;
    }
    else
        return FALSE;                           /* 使用者取消 */
}

        u_mat[1][i] = t_mat[1][i];

    l_mat[4][3] = (t_mat[4][3] - l_mat[4][1] * u_mat[1][3] - l_mat[4][2] * u_mat[2][3]) / u_mat[3][3];
    u_mat[4][4] = t_mat[4][4] - l_mat[4][1] * u_mat[1][4] - l_mat[4][2] * u_mat[2][4] - l_mat[4][3] * u_mat[3][4];
    u_mat[4][5] = t_mat[4][5] - l_mat[4][1] * u_mat[1][5] - l_mat[4][2] * u_mat[2][5] - l_mat[4][3] * u_mat[3][5];

restart: ;   /* 重新開始標籤（目前未真正使用迴圈，保留原結構） */

     * 使用者介面：選擇齒形標準
     * uc1603 顯示選項清單，回傳值 5~10 對應選項 1~6

        goto ending1;

        clearance  = 0.25 * module;

        break;
    case 5: /* Coarse-pitch 25 deg */
        pressure_angle = 25.0;
        base_rad   = pitch_rad * cos(pressure_angle * DEGRA);
        addendum   = 1.00 * module;
        deddendum  = 1.25 * module;
        clearance  = 0.25 * module;
        max_fillet = 0.30 * module;
        break;
    case 6: /* Fine-pitch 20 deg */
        pressure_angle = 20.0;
        base_rad   = pitch_rad * cos(pressure_angle * DEGRA);
        addendum   = 1.00 * module;
        deddendum  = 1.25 * module + 0.05;   /* 額外 0.05 mm 最小清除 */
        clearance  = 0.25 * module + 0.05;
        max_fillet = 0.30 * module;
        break;
    default:
        goto ending1;
    }

    /* 計算根圓半徑與齒頂圓直徑 */
    root_rad = pitch_rad - deddendum;
    gear_od  = (pitch_rad + addendum) * 2.0;

    /* 齒頂對應的展開參數 theta2 */
    sub1   = (pitch_rad + addendum) / base_rad;
    theta2 = sqrt(sub1 * sub1 - 1.0);

    /* 準備圓柱建立用的字串表達式 */
    sprintf(gear_od_st, "%f", gear_od);
    sprintf(tooth_length_st, "TOOTH_LENGTH1=%f", tooth_length);

    /* 建立毛胚圓柱（直徑 = 齒頂圓、高度 = 齒寬） */
    UF_MODL_create_cyl1(UF_NULLSIGN, origin, tooth_length_st, gear_od_st,
                        zc_dir, &cyl_tag);

    /* 擠出限制字串（起點 0、終點為齒寬表達式） */
    strcpy(limit0_buf, "0.0");
    strcpy(limit1_buf, "TOOTH_LENGTH1");
    limit1[0] = limit0_buf;
    limit1[1] = limit1_buf;

    /* 判斷使用哪種方法建立齒根
     * method 0：root_rad < base_rad → 需要額外徑向線連到基圓
     * method 1：root_rad >= base_rad → 漸開線直接從根圓開始
     */
    if (root_rad < base_rad)
        method = 0;
    else
        method = 1;

    switch (method)
    {
    /* ================================================================
     * case 0：root_rad < base_rad
     * 漸開線從基圓開始，需額外建立從根圓到基圓的徑向線，再做 fillet
     * ================================================================ */
    case 0:
        /* 從 t=0（基圓）到 t=theta2（齒頂）取 6 點 */
        theta1 = 0.0;
        theta3 = 0.0;
        delta_theta = (theta2 - theta1) / 5.0;
        for (i = 0; i < 6; i++)
        {
            /* 漸開線參數方程 */
            b_mat[i][0] = base_rad * sin(theta3) - base_rad * theta3 * cos(theta3);
            b_mat[i][1] = base_rad * cos(theta3) + base_rad * theta3 * sin(theta3);
            theta3 += delta_theta;
        }

        /* ----- Forward substitution（解 Ly = b） ----- */
        y_mat[0][0] = b_mat[0][0] / l_mat[0][0];
        y_mat[0][1] = b_mat[0][1] / l_mat[0][0];
        y_mat[1][0] = (b_mat[1][0] - l_mat[1][0] * y_mat[0][0]) / l_mat[1][1];
        y_mat[1][1] = (b_mat[1][1] - l_mat[1][0] * y_mat[0][1]) / l_mat[1][1];
        y_mat[2][0] = (b_mat[2][0] - l_mat[2][0] * y_mat[0][0] - l_mat[2][1] * y_mat[1][0]) / l_mat[2][2];
        y_mat[2][1] = (b_mat[2][1] - l_mat[2][0] * y_mat[0][1] - l_mat[2][1] * y_mat[1][1]) / l_mat[2][2];
        y_mat[3][0] = (b_mat[3][0] - l_mat[3][0] * y_mat[0][0] - l_mat[3][1] * y_mat[1][0] - l_mat[3][2] * y_mat[2][0]) / l_mat[3][3];
        y_mat[3][1] = (b_mat[3][1] - l_mat[3][0] * y_mat[0][1] - l_mat[3][1] * y_mat[1][1] - l_mat[3][2] * y_mat[2][1]) / l_mat[3][3];
        y_mat[4][0] = (b_mat[4][0] - l_mat[4][0] * y_mat[0][0] - l_mat[4][1] * y_mat[1][0] - l_mat[4][2] * y_mat[2][0]
                       - l_mat[4][3] * y_mat[3][0]) / l_mat[4][4];
        y_mat[4][1] = (b_mat[4][1] - l_mat[4][0] * y_mat[0][1] - l_mat[4][1] * y_mat[1][1] - l_mat[4][2] * y_mat[2][1]
                       - l_mat[4][3] * y_mat[3][1]) / l_mat[4][4];
        y_mat[5][0] = (b_mat[5][0] - l_mat[5][0] * y_mat[0][0] - l_mat[5][1] * y_mat[1][0] - l_mat[5][2] * y_mat[2][0]
                       - l_mat[5][3] * y_mat[3][0] - l_mat[5][4] * y_mat[4][0]) / l_mat[5][5];
        /* 修正：補上原本遺漏的 * y_mat[4][1] */
        y_mat[5][1] = (b_mat[5][1] - l_mat[5][0] * y_mat[0][1] - l_mat[5][1] * y_mat[1][1] - l_mat[5][2] * y_mat[2][1]
                       - l_mat[5][3] * y_mat[3][1] - l_mat[5][4] * y_mat[4][1]) / l_mat[5][5];

        /* ----- Back substitution（解 Ux = y）得到控制點 poles ----- */
        poles[5][0] = y_mat[5][0];
        poles[5][1] = y_mat[5][1];
        poles[4][0] = (y_mat[4][0] - u_mat[4][5] * poles[5][0]) / u_mat[4][4];
        poles[4][1] = (y_mat[4][1] - u_mat[4][5] * poles[5][1]) / u_mat[4][4];
        poles[3][0] = (y_mat[3][0] - u_mat[3][4] * poles[4][0] - u_mat[3][5] * poles[5][0]) / u_mat[3][3];
        poles[3][1] = (y_mat[3][1] - u_mat[3][4] * poles[4][1] - u_mat[3][5] * poles[5][1]) / u_mat[3][3];
        poles[2][0] = (y_mat[2][0] - u_mat[2][3] * poles[3][0] - u_mat[2][4] * poles[4][0] - u_mat[2][5] * poles[5][0]) / u_mat[2][2];
        poles[2][1] = (y_mat[2][1] - u_mat[2][3] * poles[3][1] - u_mat[2][4] * poles[4][1] - u_mat[2][5] * poles[5][1]) / u_mat[2][2];
        poles[1][0] = (y_mat[1][0] - u_mat[1][2] * poles[2][0] - u_mat[1][3] * poles[3][0] - u_mat[1][4] * poles[4][0]
                       - u_mat[1][5] * poles[5][0]) / u_mat[1][1];
        poles[1][1] = (y_mat[1][1] - u_mat[1][2] * poles[2][1] - u_mat[1][3] * poles[3][1] - u_mat[1][4] * poles[4][1]
                       - u_mat[1][5] * poles[5][1]) / u_mat[1][1];
        poles[0][0] = y_mat[0][0] - u_mat[0][1] * poles[1][0] - u_mat[0][2] * poles[2][0] - u_mat[0][3] * poles[3][0]
                      - u_mat[0][4] * poles[4][0] - u_mat[0][5] * poles[5][0];
        poles[0][1] = y_mat[0][1] - u_mat[0][1] * poles[1][1] - u_mat[0][2] * poles[2][1] - u_mat[0][3] * poles[3][1]
                      - u_mat[0][4] * poles[4][1] - u_mat[0][5] * poles[5][1];

        /* 強制基圓起點的 X 為 0（對稱） */
        poles[1][0] = 0.0;
        poles[0][0] = 0.0;

        /* 計算旋轉角度，使齒槽中心對準 +Y */
        rad2     = pitch_dia / 2.0;
        sub1     = rad2 / base_rad;
        sub1sq   = sub1 * sub1;
        theta_p  = sqrt(sub1sq - 1.0);
        x_pitch  = base_rad * sin(theta_p) - base_rad * theta_p * cos(theta_p);
        rot_angle = PI / (2.0 * teeth_no) - asin(x_pitch / rad2);

        /* 旋轉得到左側控制點 poles1，右側為鏡射 poles2 */
        for (i = 0; i < 6; i++)
        {
            poles1[i][0] = poles[i][0] * cos(-rot_angle) - poles[i][1] * sin(-rot_angle);
            poles1[i][1] = poles[i][0] * sin(-rot_angle) + poles[i][1] * cos(-rot_angle);
            poles1[i][2] = 0.0;
        }
        for (i = 0; i < 6; i++)
        {
            poles2[i][0] = -poles1[i][0];
            poles2[i][1] =  poles1[i][1];
            poles2[i][2] =  0.0;
        }

        /* 建立左側樣條 */
        for (i = 0; i < 6; i++)
        {
            pole_array[i * 4 + 0] = poles1[i][0];
            pole_array[i * 4 + 1] = poles1[i][1];
            pole_array[i * 4 + 2] = 0.0;
            pole_array[i * 4 + 3] = 1.0;         /* 權重 */
        }
        UF_CALL(UF_MODL_create_spline(POLES, ORDER, knotseq, pole_array,
                                      &lh_spline, &k_fixup, &p_fixup));

        /* 建立右側樣條 */
        for (i = 0; i < 6; i++)
        {
            pole_array[i * 4 + 0] = poles2[i][0];
            pole_array[i * 4 + 1] = poles2[i][1];
            pole_array[i * 4 + 2] = 0.0;
            pole_array[i * 4 + 3] = 1.0;
        }
        UF_CALL(UF_MODL_create_spline(POLES, ORDER, knotseq, pole_array,
                                      &rh_spline, &k_fixup, &p_fixup));

        /* 齒頂弧（三點：左頂點、頂點中點、右頂點） */
        point1[0] = 0.0;
        point1[1] = pitch_dia / 2.0 + addendum;
        point1[2] = 0.0;
        UF_CURVE_create_arc_thru_3pts(create_flag, &poles1[5][0], point1, &poles2[5][0], &od_arc_tag);

        /* 左側：從根圓到漸開線起點的徑向線 */
        UF_MODL_ask_curve_props(lh_spline, 0.0, point1, tangent1, junk3, junk3, junk3, junk3);
        UF_VEC3_angle_between(vec_x, &poles1[0][0], zc_dir, &start_angle);
        point2[0] = root_rad * cos(start_angle);
        point2[1] = root_rad * sin(start_angle);
        point2[2] = 0.0;
        ln1.start_point[0] = point2[0];
        ln1.start_point[1] = point2[1];
        ln1.start_point[2] = 0.0;
        ln1.end_point[0]   = point1[0];
        ln1.end_point[1]   = point1[1];
        ln1.end_point[2]   = 0.0;
        UF_CALL(UF_CURVE_create_line(&ln1, &lh_base_spline));

        /* 右側徑向線 */
        UF_MODL_ask_curve_props(rh_spline, 0.0, point1, tangent1, junk3, junk3, junk3, junk3);
        UF_VEC3_angle_between(vec_x, &poles2[0][0], zc_dir, &end_angle);
        point3[0] = root_rad * cos(end_angle);
        point3[1] = root_rad * sin(end_angle);
        point3[2] = 0.0;
        ln1.start_point[0] = point3[0];
        ln1.start_point[1] = point3[1];
        ln1.start_point[2] = 0.0;
        ln1.end_point[0]   = point1[0];
        ln1.end_point[1]   = point1[1];
        ln1.end_point[2]   = 0.0;
        UF_CALL(UF_CURVE_create_line(&ln1, &rh_base_spline));

        /* 計算徑向線長度，決定 fillet 做法 */
        UF_VEC3_distance(point3, point1, &length1);

        /* 齒根弧（三點：左根點、根圓中點、右根點） */
        point1[0] = 0.0;
        point1[1] = root_rad;
        point1[2] = 0.0;
        UF_CURVE_create_arc_thru_3pts(create_flag, point2, point1, point3, &root_arc_tag);

        if (length1 > max_fillet)
        {
            /* 徑向線夠長 → 在根弧與徑向線之間做 fillet */
            curve_obj[0] = root_arc_tag;
            curve_obj[1] = lh_base_spline;
            point1[0] = poles1[0][0] - max_fillet;
            point1[1] = poles1[0][1] - max_fillet;
            point1[2] = 0.0;
            trim_opts[0] = TRUE;
            trim_opts[1] = TRUE;
            arc_opts[0]  = UF_CURVE_TANGENT_OUTSIDE;
            arc_opts[1]  = 0;
            UF_CURVE_create_fillet(UF_CURVE_2_CURVE, curve_obj, point1,
                                   max_fillet, trim_opts, arc_opts, &lh_fillet);

            curve_obj[0] = rh_base_spline;
            curve_obj[1] = root_arc_tag;
            point1[0] = poles2[0][0] + max_fillet;
            point1[1] = poles2[0][1] - max_fillet;
            point1[2] = 0.0;
            trim_opts[0] = TRUE;
            trim_opts[1] = TRUE;
            arc_opts[1]  = UF_CURVE_TANGENT_OUTSIDE;
            UF_CURVE_create_fillet(UF_CURVE_2_CURVE, curve_obj, point1,
                                   max_fillet, trim_opts, arc_opts, &rh_fillet);

            /* 組成封閉迴圈並擠出減去 */
            UF_CALL(UF_MODL_create_list(&loop_list));
            UF_CALL(UF_MODL_put_list_item(loop_list, od_arc_tag));
            UF_CALL(UF_MODL_put_list_item(loop_list, lh_spline));
            UF_CALL(UF_MODL_put_list_item(loop_list, lh_base_spline));
            UF_CALL(UF_MODL_put_list_item(loop_list, lh_fillet));
            UF_CALL(UF_MODL_put_list_item(loop_list, root_arc_tag));
            UF_CALL(UF_MODL_put_list_item(loop_list, rh_fillet));
            UF_CALL(UF_MODL_put_list_item(loop_list, rh_base_spline));
            UF_CALL(UF_MODL_put_list_item(loop_list, rh_spline));
            UF_MODL_create_extruded1(loop_list, taper_angle, limit1,
                                     origin, zc_dir, UF_NEGATIVE, cyl_tag, &features);
            UF_CALL(UF_MODL_ask_list_item(features, 0, &tooth_gap_tag));
            UF_MODL_delete_list(&loop_list);
            UF_MODL_delete_list(&features);

            /* 準備 Pattern 用的列表，並隱藏建構曲線 */
            UF_CALL(UF_MODL_create_list(&loop_list));
            UF_CALL(UF_MODL_put_list_item(loop_list, tooth_gap_tag));
            UF_OBJ_set_blank_status(od_arc_tag, UF_OBJ_BLANKED);
            UF_OBJ_set_blank_status(lh_spline, UF_OBJ_BLANKED);
            UF_OBJ_set_blank_status(lh_base_spline, UF_OBJ_BLANKED);
            UF_OBJ_set_blank_status(lh_fillet, UF_OBJ_BLANKED);
            UF_OBJ_set_blank_status(root_arc_tag, UF_OBJ_BLANKED);
            UF_OBJ_set_blank_status(rh_fillet, UF_OBJ_BLANKED);
            UF_OBJ_set_blank_status(rh_base_spline, UF_OBJ_BLANKED);
            UF_OBJ_set_blank_status(rh_spline, UF_OBJ_BLANKED);
        }
        else /* length1 <= max_fillet：徑向線太短，直接在樣條與根弧做 fillet */
        {
            curve_obj[0] = root_arc_tag;
            curve_obj[1] = lh_spline;
            point1[0] = poles1[0][0] - max_fillet;
            point1[1] = poles1[0][1] + max_fillet;
            point1[2] = 0.0;
            trim_opts[0] = TRUE;
            trim_opts[1] = TRUE;
            arc_opts[0]  = UF_CURVE_TANGENT_OUTSIDE;
            arc_opts[1]  = 0;
            UF_CURVE_create_fillet(UF_CURVE_2_CURVE, curve_obj, point1,
                                   max_fillet, trim_opts, arc_opts, &lh_fillet);

            curve_obj[0] = rh_spline;
            curve_obj[1] = root_arc_tag;
            point1[0] = poles2[0][0] + max_fillet;
            point1[1] = poles2[0][1] + max_fillet;
            point1[2] = 0.0;
            trim_opts[0] = TRUE;
            trim_opts[1] = TRUE;
            arc_opts[1]  = UF_CURVE_TANGENT_OUTSIDE;
            UF_CURVE_create_fillet(UF_CURVE_2_CURVE, curve_obj, point1,
                                   max_fillet, trim_opts, arc_opts, &rh_fillet);

            /* 刪除不再需要的徑向線 */
            if (lh_base_spline != NULL_TAG)
                UF_OBJ_delete_object(lh_base_spline);
            if (rh_base_spline != NULL_TAG)
                UF_OBJ_delete_object(rh_base_spline);

            UF_CALL(UF_MODL_create_list(&loop_list));
            UF_CALL(UF_MODL_put_list_item(loop_list, od_arc_tag));
            UF_CALL(UF_MODL_put_list_item(loop_list, lh_spline));
            UF_CALL(UF_MODL_put_list_item(loop_list, lh_fillet));
            UF_CALL(UF_MODL_put_list_item(loop_list, root_arc_tag));
            UF_CALL(UF_MODL_put_list_item(loop_list, rh_fillet));
            UF_CALL(UF_MODL_put_list_item(loop_list, rh_spline));
            UF_MODL_create_extruded1(loop_list, taper_angle, limit1,
                                     origin, zc_dir, UF_NEGATIVE, cyl_tag, &features);
            UF_CALL(UF_MODL_ask_list_item(features, 0, &tooth_gap_tag));
            UF_MODL_delete_list(&loop_list);
            UF_MODL_delete_list(&features);

            UF_CALL(UF_MODL_create_list(&loop_list));
            UF_CALL(UF_MODL_put_list_item(loop_list, tooth_gap_tag));
            UF_OBJ_set_blank_status(od_arc_tag, UF_OBJ_BLANKED);
            UF_OBJ_set_blank_status(lh_spline, UF_OBJ_BLANKED);
            UF_OBJ_set_blank_status(lh_fillet, UF_OBJ_BLANKED);
            UF_OBJ_set_blank_status(root_arc_tag, UF_OBJ_BLANKED);
            UF_OBJ_set_blank_status(rh_fillet, UF_OBJ_BLANKED);
            UF_OBJ_set_blank_status(rh_spline, UF_OBJ_BLANKED);
        }
        break;

    /* ================================================================
     * case 1：root_rad >= base_rad
     * 漸開線直接從根圓開始，不需額外徑向線
     * ================================================================ */
    case 1:
        /* 從 t=theta1（根圓）到 t=theta2（齒頂）取 6 點 */
        sub2     = (pitch_rad - deddendum) / base_rad;
        sub2sq   = sub2 * sub2;
        theta1   = sqrt(sub2sq - 1.0);
        theta3   = theta1;
        delta_theta = (theta2 - theta1) / 5.0;
        for (i = 0; i < 6; i++)
        {
            b_mat[i][0] = base_rad * sin(theta3) - base_rad * theta3 * cos(theta3);
            b_mat[i][1] = base_rad * cos(theta3) + base_rad * theta3 * sin(theta3);
            theta3 += delta_theta;
        }

        /* Forward + Back substitution（同 case 0） */
        y_mat[0][0] = b_mat[0][0] / l_mat[0][0];
        y_mat[0][1] = b_mat[0][1] / l_mat[0][0];
        y_mat[1][0] = (b_mat[1][0] - l_mat[1][0] * y_mat[0][0]) / l_mat[1][1];
        y_mat[1][1] = (b_mat[1][1] - l_mat[1][0] * y_mat[0][1]) / l_mat[1][1];
        y_mat[2][0] = (b_mat[2][0] - l_mat[2][0] * y_mat[0][0] - l_mat[2][1] * y_mat[1][0]) / l_mat[2][2];
        y_mat[2][1] = (b_mat[2][1] - l_mat[2][0] * y_mat[0][1] - l_mat[2][1] * y_mat[1][1]) / l_mat[2][2];
        y_mat[3][0] = (b_mat[3][0] - l_mat[3][0] * y_mat[0][0] - l_mat[3][1] * y_mat[1][0] - l_mat[3][2] * y_mat[2][0]) / l_mat[3][3];
        y_mat[3][1] = (b_mat[3][1] - l_mat[3][0] * y_mat[0][1] - l_mat[3][1] * y_mat[1][1] - l_mat[3][2] * y_mat[2][1]) / l_mat[3][3];
        y_mat[4][0] = (b_mat[4][0] - l_mat[4][0] * y_mat[0][0] - l_mat[4][1] * y_mat[1][0] - l_mat[4][2] * y_mat[2][0]
                       - l_mat[4][3] * y_mat[3][0]) / l_mat[4][4];
        y_mat[4][1] = (b_mat[4][1] - l_mat[4][0] * y_mat[0][1] - l_mat[4][1] * y_mat[1][1] - l_mat[4][2] * y_mat[2][1]
                       - l_mat[4][3] * y_mat[3][1]) / l_mat[4][4];
        y_mat[5][0] = (b_mat[5][0] - l_mat[5][0] * y_mat[0][0] - l_mat[5][1] * y_mat[1][0] - l_mat[5][2] * y_mat[2][0]
                       - l_mat[5][3] * y_mat[3][0] - l_mat[5][4] * y_mat[4][0]) / l_mat[5][5];
        y_mat[5][1] = (b_mat[5][1] - l_mat[5][0] * y_mat[0][1] - l_mat[5][1] * y_mat[1][1] - l_mat[5][2] * y_mat[2][1]
                       - l_mat[5][3] * y_mat[3][1] - l_mat[5][4] * y_mat[4][1]) / l_mat[5][5];

        poles[5][0] = y_mat[5][0];
        poles[5][1] = y_mat[5][1];
        poles[4][0] = (y_mat[4][0] - u_mat[4][5] * poles[5][0]) / u_mat[4][4];
        poles[4][1] = (y_mat[4][1] - u_mat[4][5] * poles[5][1]) / u_mat[4][4];
        poles[3][0] = (y_mat[3][0] - u_mat[3][4] * poles[4][0] - u_mat[3][5] * poles[5][0]) / u_mat[3][3];
        poles[3][1] = (y_mat[3][1] - u_mat[3][4] * poles[4][1] - u_mat[3][5] * poles[5][1]) / u_mat[3][3];
        poles[2][0] = (y_mat[2][0] - u_mat[2][3] * poles[3][0] - u_mat[2][4] * poles[4][0] - u_mat[2][5] * poles[5][0]) / u_mat[2][2];
        poles[2][1] = (y_mat[2][1] - u_mat[2][3] * poles[3][1] - u_mat[2][4] * poles[4][1] - u_mat[2][5] * poles[5][1]) / u_mat[2][2];
        poles[1][0] = (y_mat[1][0] - u_mat[1][2] * poles[2][0] - u_mat[1][3] * poles[3][0] - u_mat[1][4] * poles[4][0]
                       - u_mat[1][5] * poles[5][0]) / u_mat[1][1];
        poles[1][1] = (y_mat[1][1] - u_mat[1][2] * poles[2][1] - u_mat[1][3] * poles[3][1] - u_mat[1][4] * poles[4][1]
                       - u_mat[1][5] * poles[5][1]) / u_mat[1][1];
        poles[0][0] = y_mat[0][0] - u_mat[0][1] * poles[1][0] - u_mat[0][2] * poles[2][0] - u_mat[0][3] * poles[3][0]
                      - u_mat[0][4] * poles[4][0] - u_mat[0][5] * poles[5][0];
        poles[0][1] = y_mat[0][1] - u_mat[0][1] * poles[1][1] - u_mat[0][2] * poles[2][1] - u_mat[0][3] * poles[3][1]
                      - u_mat[0][4] * poles[4][1] - u_mat[0][5] * poles[5][1];

        /* 旋轉對準 +Y */
        rad2     = pitch_dia / 2.0;
        sub1     = rad2 / base_rad;
        sub1sq   = sub1 * sub1;
        theta_p  = sqrt(sub1sq - 1.0);
        x_pitch  = base_rad * sin(theta_p) - base_rad * theta_p * cos(theta_p);
        rot_angle = PI / (2.0 * teeth_no) - asin(x_pitch / rad2);

        for (i = 0; i < 6; i++)
        {
            poles1[i][0] = poles[i][0] * cos(-rot_angle) - poles[i][1] * sin(-rot_angle);
            poles1[i][1] = poles[i][0] * sin(-rot_angle) + poles[i][1] * cos(-rot_angle);
            poles1[i][2] = 0.0;
        }
        for (i = 0; i < 6; i++)
        {
            poles2[i][0] = -poles1[i][0];
            poles2[i][1] =  poles1[i][1];
            poles2[i][2] =  0.0;
        }

        /* 建立左/右樣條 */
        for (i = 0; i < 6; i++)
        {
            pole_array[i * 4 + 0] = poles1[i][0];
            pole_array[i * 4 + 1] = poles1[i][1];
            pole_array[i * 4 + 2] = 0.0;
            pole_array[i * 4 + 3] = 1.0;
        }
        UF_CALL(UF_MODL_create_spline(POLES, ORDER, knotseq, pole_array,
                                      &lh_spline, &k_fixup, &p_fixup));

        for (i = 0; i < 6; i++)
        {
            pole_array[i * 4 + 0] = poles2[i][0];
            pole_array[i * 4 + 1] = poles2[i][1];
            pole_array[i * 4 + 2] = 0.0;
            pole_array[i * 4 + 3] = 1.0;
        }
        UF_CALL(UF_MODL_create_spline(POLES, ORDER, knotseq, pole_array,
                                      &rh_spline, &k_fixup, &p_fixup));

        /* 齒頂弧 */
        point1[0] = 0.0;
        point1[1] = pitch_dia / 2.0 + addendum;
        point1[2] = 0.0;
        UF_CURVE_create_arc_thru_3pts(create_flag, &poles1[5][0], point1, &poles2[5][0], &od_arc_tag);

        /* 齒根弧（直接用樣條起點） */
        point1[0] = 0.0;
        point1[1] = root_rad;
        point1[2] = 0.0;
        UF_CURVE_create_arc_thru_3pts(create_flag, &poles1[0][0], point1, &poles2[0][0], &root_arc_tag);

        /* 左 fillet：根弧 + 左樣條，help point 在交點上方 */
        curve_obj[0] = root_arc_tag;
        curve_obj[1] = lh_spline;
        point1[0] = poles1[0][0];
        point1[1] = poles1[0][1] + max_fillet / 2.0;
        point1[2] = 0.0;
        trim_opts[0] = TRUE;
        trim_opts[1] = TRUE;
        arc_opts[0]  = UF_CURVE_TANGENT_OUTSIDE;
        arc_opts[1]  = 0;
        UF_CURVE_create_fillet(UF_CURVE_2_CURVE, curve_obj, point1, max_fillet, trim_opts, arc_opts, &lh_fillet);

        /* 右 fillet */
        curve_obj[0] = rh_spline;
        curve_obj[1] = root_arc_tag;
        point1[0] = poles2[0][0];
        point1[1] = poles2[0][1] + max_fillet / 2.0;
        point1[2] = 0.0;
        trim_opts[0] = TRUE;
        trim_opts[1] = TRUE;
        arc_opts[1]  = UF_CURVE_TANGENT_OUTSIDE;
        UF_CURVE_create_fillet(UF_CURVE_2_CURVE, curve_obj, point1, max_fillet, trim_opts, arc_opts, &rh_fillet);

        /* 組成封閉迴圈並擠出 */
        UF_CALL(UF_MODL_create_list(&loop_list));
        UF_CALL(UF_MODL_put_list_item(loop_list, od_arc_tag));
        UF_CALL(UF_MODL_put_list_item(loop_list, lh_spline));
        UF_CALL(UF_MODL_put_list_item(loop_list, lh_fillet));
        UF_CALL(UF_MODL_put_list_item(loop_list, root_arc_tag));
        UF_CALL(UF_MODL_put_list_item(loop_list, rh_fillet));
        UF_CALL(UF_MODL_put_list_item(loop_list, rh_spline));
        UF_MODL_create_extruded1(loop_list, taper_angle, limit1,
                                 origin, zc_dir, UF_NEGATIVE, cyl_tag, &features);
        UF_CALL(UF_MODL_ask_list_item(features, 0, &tooth_gap_tag));
        UF_MODL_delete_list(&loop_list);
        UF_MODL_delete_list(&features);

        UF_CALL(UF_MODL_create_list(&loop_list));
        UF_CALL(UF_MODL_put_list_item(loop_list, tooth_gap_tag));
        UF_OBJ_set_blank_status(od_arc_tag, UF_OBJ_BLANKED);
        UF_OBJ_set_blank_status(lh_spline, UF_OBJ_BLANKED);
        UF_OBJ_set_blank_status(lh_fillet, UF_OBJ_BLANKED);
        UF_OBJ_set_blank_status(root_arc_tag, UF_OBJ_BLANKED);
        UF_OBJ_set_blank_status(rh_fillet, UF_OBJ_BLANKED);
        UF_OBJ_set_blank_status(rh_spline, UF_OBJ_BLANKED);
        break;
    }

    /* ================================================================
     * Circular Pattern：把單一齒槽特徵繞 Z 軸複製 teeth_no 次
     * ================================================================ */
    int_teeth_no = (int)(teeth_no + 0.5);
    sprintf(teeth_no_st, "%d", int_teeth_no);
    angle1 = 360.0 / teeth_no;
    sprintf(angle_st, "%f", angle1);

    /* method1 = 0 表示使用角度增量方式 */
    UF_MODL_create_circular_iset(method1, origin, zc_dir, teeth_no_st, angle_st, loop_list, &instances);

    /* 取得所有實例並組成特徵群組 */
    UF_MODL_ask_instance(instances, &instances_feature_list);
    UF_CALL(UF_MODL_ask_list_count(instances_feature_list, &num_instances));
    for (i = 0; i < num_instances && i < 240; i++)
    {
        UF_CALL(UF_MODL_ask_list_item(instances_feature_list, i, &temp_tag));
        teeth_tag[i] = temp_tag;
    }
    UF_MODL_create_set_of_feature("Teeth_set", &teeth_tag[0], num_instances, 1, &teeth_grp_tag);

ending1: ;
    /* 調整視圖使整個齒輪可見 */
    UF_CALL(UF_VIEW_fit_view(NULL_TAG, 1.0));
}

Datum

在 UGS NX3 中，建立基準面（Datum Plane）是構建三維空間幾何基準的最核心操作。NX 提供多種靈活的演算法，讓你能根據現有的點、線、面或角度來定位。

以下為最常用的 7 種建立基準面的操作步驟：

在開始以下任何一種方法前，請先執行：點選特徵工具列的 基準面 (Datum Plane) 圖示，或依序點選功能選單：插入 (Insert) -> 基準/座標系 (Datum/CSYS) -> 基準面 (Datum Plane)。

方法一：偏置基準面（Offset）

  1. 最常用，與現有平面保持特定垂直距離。
  2. 選擇類型：將對話框中的類型（Type）切換為 偏置 (Offset)。
  3. 選取參考面：點選現有的平整表面、既有基準面或座標平面（如 XY 平面）。
  4. 設定距離：在 距離 (Distance) 欄位輸入數值（例如：50mm）。
  5. 調整方向與數量：點選 反向 (Reverse Direction) 箭頭可切換偏置方向。調整 數量 (Number) 可一次建立多個等距離的平行面。
  6. 完成：點選 確定 (OK)。

方法二：成一角度（At an Angle / 傾斜面）

  1. 圍繞一條軸線旋轉特定角度，適合製作斜面或拔模基準。
  2. 選擇類型：切換為 成一角度 (At an Angle)。
  3. 選取旋轉軸：點選一條直線、實體邊緣或基準軸（作為旋轉的中心軸）。
  4. 選取參考面：點選一個與該軸平行的平面（作為計算 0 度的基準面）。
  5. 設定角度：在 角度 (Angle) 欄位輸入所需的角度值（例如：45度）。
  6. 完成：點選 確定 (OK)。

方法三：二等分面（Bisector / 中立面）

  1. 在兩個平行或成角度的平面正中間建立一個對稱面，極利於對稱零件建模。
  2. 選擇類型：切換為 二等分面 (Bisector)。
  3. 選取第一面：點選第一個平面。
  4. 選取第二面：點選第二個平行或相交的平面。
  5. 完成：系統會自動計算並將基準面精確定位在兩面正中央，點選 確定 (OK)。

方法四：通過三點（Through Three Points）

  1. 在非正交的任意空間中，利用三個不共線的點決定一個特殊平面。
  2. 選擇類型：切換為 通過三點 (Through Three Points)。
  3. 選取點：在 3D 空間中依序點選 點 1、點 2、點 3。
  4. 註：點可以是草圖頂點、實體角點、圓心或基準點。選取時可配合畫面上方的「點過濾器（Point Snap）」以精確捕捉。
  5. 完成：點選 確定 (OK)。

方法五：點和一條線（Point and Direction / 過點且垂直/平行）

  1. 通過一個特定點，並與某一條直線或向量垂直或平行。
  2. 選擇類型：切換為 點和方向 (Point and Direction) 或相關點線組合。
  3. 選取參考點：點選空間中的任意一個已知點。
  4. 選取直線/向量：點選一條實體邊、基準軸，或直接點選座標軸指定向量方向。設定幾何關係：在設定中選擇使平面 平行 (Parallel) 或 垂直 (Perpendicular) 於該線。
  5. 完成：點選 確定 (OK)。

方法六：相切於曲面（Tangent / 切面）

  1. 在圓柱面、圓錐面或任意曲面上建立一個相切的平面。
  2. 選擇類型：切換為 相切 (Tangent)。
  3. 選取曲面：點選圓柱體的外側曲面。
  4. 指定定位參考（可選）：若只選曲面，基準面可能會繞著圓柱轉動。此時可以再選一個空間平面，並指定「與其平行」或「與其成一角度」，來精確固定切面的方位。
  5. 完成：點選 確定 (OK)。

方法七：基於路徑（On Path / 曲線剖切面）

  1. 沿著一條曲線（如掃掠路徑）建立一個垂直於該曲線切線的平面，常用於建立掃掠（Sweep）的截面草圖。
  2. 選擇類型：切換為 基於路徑 (On Path)。
  3. 選取路徑曲線：點選一條草圖線、實體邊緣或不規則曲線。
  4. 設定位置（Location）：可以輸入 弧長（Arc Length） 或是 百分比（Percentage）。例如：輸入百分比 0 代表曲線起點；輸入 50 代表曲線正中央；輸入 100 代表曲線終點。也可以用滑鼠直接在畫面的曲線上拖曳黃色箭頭來決定位置。
  5. 完成：點選 確定 (OK)。

用上述任何一種方法建立好基準面後，不管它的預設方向為何，只要在啟動 草圖 (Sketch) 指令並點選該面時，在對話框中展開 草圖定向 (Sketch Orientation) 欄位，手動用 水平 (Horizontal) 參考去抓取空間中的絕對 X 軸、Y 軸或實體邊緣，就能完全主導草圖內部的 X-Y 軸方位。

Associated Copy (AC)

UGS NX3 允許使用者在 Part Navigator 中以滑鼠加上 Ctrl 選擇一個以上的 Features，然後再利用滑鼠帶出其中有 Group 的表單，利用此表單的 Group 可以將所選多個 Features 以群組名稱命名。

Format - Group 功能的說明:

UGS NX 3 的 Format → Group 是一種持久性的模型物件組織機制，用於將一個或多個 NX objects 以指定名稱建立為邏輯群組，並將該群組顯示於 Model Navigator。Group membership 不改變成員物件本身的幾何、Feature dependency 或參數化歷史，其主要用途在於模型結構管理、工程語意分類及後續選取／管理。

先替一批 NX objects 建立一個有名稱的「可被重新找回、重新選取、重新管理的集合」，之後其他操作需要這批物件時，可以透過這個 Group 找回這批物件，而不必重新逐一選取。

Shape Studio (SS)

在 UG/NX3（2004 年發佈）中，Shape Studio（工業設計與造型模組） 是 Siemens 專為汽車外觀、消費性電子產品與高階工業設計所打造的「進階曲面造型利器」。SS 擺脫了傳統機械設計（如單純的拉伸、旋轉）的生硬感，核心特色是提供強大的 Class-A（A級曲面） 建立與分析工具，讓工程師能設計出極具流線感、滑順且符合美學的高難度曲面。

UGS NX3 Shape Studio 的 4 大核心特色

一、高階 A 級曲面建立功能 (Class-A Styling)

  1. 藝術曲面 (Studio Surface)：Shape Studio 的靈魂功能。可以同時限制多條截面導引線，並嚴格控制邊界處的曲面連續性（G0、G1、G2），是做出流線型外殼最常用的指令。
  2. 變形造型 (Global Shaping)：允許設計師像拉扯橡膠墊一樣，對一整塊現有的複雜 3D 模型進行整體的彎曲、拉伸或扭曲，適合用來做概念概念車身或人體工學滑鼠造形。

二、強大且嚴苛的曲面品質分析 (Surface Analysis)

在美學設計中，外觀微小的凹凸都會影響反光。Shape Studio 內建了當時最頂尖的檢測工具：

  1. 高光線分析 (Reflection Lines / Zebra Strips)：在曲面上投射虛擬的黑白斑馬線。如果斑馬線在曲面接縫處是斷開的，代表曲面不連續；如果線條平滑銜接，代表達到了頂級的 G2 曲面（曲率連續）。
  2. 曲率梳分析 (Curvature Combs)：用梳子狀的線條檢測曲線的平滑度。

三、混合建模 (Hybrid Modeling)

將「自由曲面（Freeform）」與「實體建模（Solid）」完美結合。設計者可以在 Shape Studio 裡用曲面切削實體，或是將多個曲面縫合（Sew）直接變成實體，不需要在不同的軟體間轉檔。

四、動態動態雕刻 (Dynamic Sculpting)

可以直接透過拖曳曲面上的 控制點（Control Points / Poles） 來微調曲面。讓工程師能像雕刻師一樣，憑直覺微調產品線條。

Open C

這裡的 Open C 指用來開發 UGS NX3 的 API 程式庫。

Open C API is designed to enable an easy interface between NX and the outside world. The Open C API consists of:

  1. a large set of user callable functions/subroutines that access the NX Graphics Terminal, File Manager, and Database.
  2. command procedures to link and run user programs.
  3. an interactive interface in NX to run those programs.

Open C API programs can run in 2 different environments, depending on how the program was linked.

The two environments are:

External - these Open C API programs are stand alone programs that can run from the operating system, outside of NX, or as a child process spawned from NX.

Internal - these Open C API programs can only be run from inside of an NX session. These programs are loaded into main memory along side of NX and access routines within NX. One advantage to this is that the executables are much smaller and link much faster. Once an Internal Open C API Program is loaded into memory, it can stay resident for the remainder of the NX session. If you call this program again, it executes without reloading (provided it was not unloaded). Internal Open C API programs work on the current part and automatically modify the part display.

Most Open C API functions/subroutines can be used in either mode. There are only a few, mostly User Interface routines that are only supported in internal mode.
