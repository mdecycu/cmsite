## 一、struct、derive、Vec、HashMap 等語法與資料結構

### 講解稿

各位同學好，我們今天要從這支「CMS 靜態 HTML 轉換工具」開始，一步步拆解 Rust 的核心語法。

首先看到的是資料結構。Rust 用 `struct` 來定義自己的資料型別，把相關的欄位包在一起。原程式裡有三個重要的結構體：

- `Page`：代表一個分頁，包含標題、檔名、層級和內容。
- `NavNode`：用來建立樹狀導覽選單，裡面有一個 `Vec<NavNode>`，形成父子關係。
- `SearchPage`：專門用來產生搜尋索引。

我們常會加上 `#[derive(Debug, Clone)]` 或 `#[derive(Serialize)]`，這是屬性巨集，可以自動幫我們實作常用的功能，不用自己手動寫。

另外，`Vec` 是動態陣列，可以一直加東西進去；`HashMap` 則是鍵值對，非常適合做計數或快速查找。原程式就是用 `HashMap` 來處理「標題重複」和「檔名衝突」的問題。

### 投影片重點

- `struct`：自訂資料型別，把相關欄位打包
- `#[derive(Debug, Clone, Serialize)]`：自動實作常用 Trait
- `Vec<T>`：動態陣列，最常用的集合
- `HashMap<K, V>`：鍵值對，適合計數與查找
- 原程式範例：
  - `Page`：分頁資料
  - `NavNode`：樹狀導覽節點
  - `SearchPage`：搜尋索引

**延伸例子**
1. 商品結構：`Product { id, name, price, tags }`
2. 使用 HashMap 做字頻統計
3. 巢狀資料夾結構：`Folder { name, files, subfolders }`

## 二、函式參數、回傳型別、借用、參考、生命週期及 Result、? 錯誤處理

### 講解稿

接下來我們看函式怎麼寫。

在 Rust 裡，函式參數如果寫成 `&str` 或 `&Path`，代表我們只是「借用」資料，不會把所有權拿走，這樣呼叫端還可以繼續使用原本的資料。

回傳型別很常看到 `Result<T, E>`。成功就回傳 `Ok(值)`，失敗就回傳 `Err(錯誤)`。原程式大量使用 `Box<dyn Error>`，這是一種可以代表各種錯誤的寫法。

最方便的是 `?` 運算子。只要在可能失敗的地方加上 `?`，如果發生錯誤就會自動提早回傳，成功的話就把值取出來繼續用。這讓錯誤處理變得很簡潔。

另外，Rust 的編譯器會透過「生命週期」確保參考不會比它指向的資料活得更久，這是 Rust 安全的重要基礎。

### 投影片重點

- 參數使用 `&T` / `&mut T` → 借用，不取得所有權
- 回傳 `Result<T, E>` → 成功 Ok、失敗 Err
- `?` 運算子 → 錯誤自動往上傳遞，程式碼更簡潔
- 生命週期 → 確保參考的安全性
- 原程式範例：
  - `strip_tags(input: &str) -> Result<String, Box<dyn Error>>`
  - `generate(...) -> Result<(), Box<dyn Error>>`

**延伸例子**
1. 讀取設定檔：`load_config(path: &str) -> Result<String, ...>`
2. 安全除法：除數為零時回傳 Err
3. 使用 `&mut String` 修改字串內容

## 三、正規表示式、閉包、迭代器、字串處理與檔名衝突處理

### 講解稿

這部分是文字處理的核心。

原程式使用 `regex` 這個 crate 來找 HTML 的 h1、h2、h3 標題。正規表示式可以寫得很強大，也能加上 `(?is)` 這種旗標來控制匹配行為。

接著是閉包與迭代器。Rust 的迭代器非常強大，常常搭配閉包使用。像 `chars().map(...).collect()` 這種寫法，可以把每個字元轉換後再收集成新的字串。原程式的 `slug_filename` 就是用這種方式把不合法的檔名字元換成底線。

最後是檔名衝突處理。當兩個標題產生出相同檔名時，程式會用 `HashMap` 計數，自動在後面加上 `-1`、`-2`，確保檔名唯一。

### 投影片重點

- `Regex`：用來匹配與擷取文字
- 閉包：可捕捉環境的匿名函式
- 迭代器：`map`、`filter`、`collect` 是核心
- 字串處理常用方法：`replace`、`trim`、`chars`
- 檔名衝突 → 使用 `HashMap` 計數解決
- 原程式範例：
  - `slug_filename` 使用 `chars().map().collect()`
  - 用 HashMap 處理重複檔名

**延伸例子**
1. 簡單的電子郵件格式驗證
2. 過濾偶數並計算平方
3. 自動產生不重複檔名的函式

## 四、HTML 樣板、CSS 排版、樹狀導覽、Previous／Next 分頁連結

### 講解稿

現在進入「產生網頁」的部分。

原程式使用 raw string（`r##"..."##`）來嵌入大量的 HTML、CSS 和 JavaScript，這樣就不用一直跳脫雙引號。要注意的是，在 `format!` 裡面如果要輸出大括號，必須寫成雙大括號 `{{` 和 `}}`。

導覽選單是樹狀結構。程式先用遞迴把分頁依照 h1、h2、h3 的層級建成一棵樹，再用另一個遞迴函式把樹渲染成 HTML。

Previous 和 Next 連結則做得很乾淨：同一個函式上下各呼叫一次，並使用 CSS flex 讓 Previous 靠左、Next 靠右，版面一致又好維護。

### 投影片重點

- Raw string（`r##"..."##`）方便嵌入 HTML/CSS/JS
- `format!` 中大括號要寫成 `{{` `}}`
- 樹狀導覽：遞迴建立 + 遞迴渲染
- Previous / Next：同一函式重複使用，版面統一
- CSS 使用 flex 讓左右對齊
- 原程式範例：
  - `html_header`、`render_nav_nodes`
  - `render_previous_next`

**延伸例子**
1. 簡單的 HTML 頁面樣板函式
2. 遞迴產生目錄樹 HTML
3. 通用的分頁導覽列

## 五、檔案讀寫、JSON 序列化、命令列參數及程式進入點 main()

### 講解稿

最後我們把整支程式串起來。

檔案操作很簡單：`fs::read_to_string` 讀取整個檔案，`fs::write` 寫出內容。原程式在產生每個分頁後，還會把資料收集起來，用 `serde_json` 轉成 JSON，再寫成 JavaScript 檔，供前端搜尋使用。

命令列參數透過 `env::args()` 取得。程式支援兩種使用方式：直接執行使用預設路徑，或自己指定輸入檔和輸出目錄。如果加上 `--help`，就會顯示使用說明。

`main` 函式的責任很單純：解析參數、呼叫核心邏輯、處理錯誤。真正的轉換工作都放在 `generate` 函式裡，這樣結構更清晰。

### 投影片重點

- 檔案讀寫：`fs::read_to_string`、`fs::write`
- JSON 序列化：`serde_json::to_string`
- 命令列參數：`env::args().collect()`
- `main` 只負責參數解析與錯誤處理
- 核心邏輯放在 `generate` 函式
- 原程式流程：
  1. 解析參數
  2. 讀取 content.htm
  3. 切割分頁並產生 HTML
  4. 輸出搜尋索引

**延伸例子**
1. 簡單的檔案複製函式
2. 把資料輸出成美觀的 JSON 檔
3. 完整的命令列小工具範本
